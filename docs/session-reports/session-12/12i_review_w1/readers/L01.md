### L01-C1 — A record in which no field carries a value is stored as `extracted`, never counts toward the abort, and blocks reselection
- **File / function:** `engine/core/extraction_events.py` — `counts_toward_abort`, `plan_extraction_events`; consequence in `engine/core/selection.py :: select_for_extraction`
- **Pattern:** ii (a systematic fault recorded as a completed paper)
- **Evidence level:** reproduced (pure functions)
- **Evidence:**
  `counts_toward_abort`:
  ```python
  if isinstance(outcome, ExtractionRecord):
      return not outcome.fields
  ```
  `plan_extraction_events` — the failure branch is `if not rec.fields:` only; any record with one or more `FieldOutcome` of any kind ends
  ```python
  return EventPlan(tuple(out), _paper_event(
      rec, event_type="extracted", to_state="extracted", ...
  ```
  A `CONTRACT_UNMET` or `DECLINED` field is a `FieldOutcome`, so it is in `rec.fields`. `engine/elicitation/pipeline.py` reaches this deliberately: "no field met its evidence contract … Pass 2 skipped; the terminal states are the extraction." Each `contract_unmet` event is claim-bearing and carries the reuse key, so `selection._live_reuse_keys` returns the key and `if key in _live_reuse_keys(...): skipped_asserted.append(paper_id)`.
  Reproducer `L01_2_zero_value_record.py` / `.out`: 20 of 20 fields `CONTRACT_UNMET` (`INDEX_MALFORMED`) → `paper event: extracted -> extracted reason_code = None`, `payload counts {'asserted': 0, 'contract_unmet': 20, 'declined': 0}`, `counts_toward_abort(record): False`, 20 claim-bearing events each carrying `reuse_key`.
- **What goes wrong:** a run-wide contract failure (the prompt regression CLAUDE.md records — "dropping it cost a whole smoke run" — or a runtime interface change) stores every paper as `extracted` (analysis-ready) with zero values. `CONSECUTIVE_FAILURE_ABORT` never fires (the success path also resets the counter), the run closes completed, and the next run skips every paper by reuse key. On the pinned arm the only recovery is a new arm name (R10).
- **Refutation tried:** R139/R140 rule that a contract-unmet field stores and the paper is not failed — they are about a paper with *some* trusted field ("extraction_failed is reserved for outcomes in which no field can be trusted", R139). R535's floor is "fewer than half of the expected fields" *held*; a 20-of-20 `contract_unmet` record holds all 20, so the floor as worded does not fire. The local distribution check is non-strict and is skipped under 10 papers with live claims; with zero values it has nothing categorical to flag. Grep of the plan for "0 asserted / all CONTRACT_UNMET / zero asserted" finds no row.
- **Tests:** `tests/test_cut_over.py` asserts `counts_toward_abort(empty)` for a record with no fields only; `tests/test_extraction_events.py::test_t2_an_elicited_contract_unmet_and_an_incomplete_carrier` pins the mixed case. No test builds a record whose fields are all non-values.
- **Existing row:** extends A-11 (same "stored as `extracted`, analysis-ready" outcome; new trigger — zero values rather than missing fields — and the R535 floor does not cover it)
- **Proposed class / package:** 1 / P1 — a failed run reads as a completed one and burns the pinned arm; belongs with A-11's floor.

### L01-C2 — The writer accepts a reviewer decision that names competing decisions but no claim; the reader then discards its value and silently restores the machine value

- **Evidence level:** reproduced (synthetic database under a temp dir)
- **Evidence:**

  ```python
      raise ReviewerDecisionAmbiguous(
  ...
  if against_claims and against_claims < live:
  ```
