---

**Short answer.** The row holds, and it is one case of a wider one. An old-text claim stays live
whenever a later extraction of the same paper on new text writes **no event on that cell**. That
happens for a field left incomplete (the row's case), and also for **every** field of a paper whose
re-extraction fails or is refused at selection — then all the old-text claims stay live. The reader
returns such a claim as an ordinary value: nothing in its state, rule row or provenance says the
text it came from is no longer the paper's current text. Each rule involved is built as written;
the conflict is between two rulings (R140 "no event for a missing field" and S3d "the previous
extraction is superseded"), not between a ruling and the code. Run 7's launch reaches none of it.
**I4 is partly contradicted:** audit refuses such a paper only while the stale claim is an asserted
claim that has not yet been located.

## Q1. Supersession as built — READ

`engine/core/extraction_events.py`, `plan_extraction_events`. A `superseded` event is written only
inside the loop over the new record's field outcomes:

```python
    for fo in rec.fields:
        on_cell = live.get(fo.field_name, ())
        if key is not None and any(ev.payload.get(PAYLOAD_REUSE_KEY) == key for ev in on_cell):
            raise ReuseKeyAlreadyClaimed(
        ...
        stale = {ev.claim_id for ev in on_cell}
        if stale:
            out.append(dict(base, event_type="superseded", field_name=fo.field_name,
                            actor_kind="engine", actor_role="system", actor_name="extractor",
                            against_claims=stale, reason="input identity changed",
                            payload=dict(ident)))
```

| new outcome on the cell | what is written | old claim on that cell |
|---|---|---|
| a value (`asserted`) | `superseded` against every live claim on the cell, then the new claim | superseded |
| `contract_unmet` | the same: it is a `FieldOutcome`, so it is in `rec.fields` | superseded |
| `declined` | the same | superseded |
| field in `incomplete_fields` | **nothing.** The name is listed in the `extracted` paper event's payload (`"incomplete_fields": list(rec.incomplete_fields)`) | **stays live** |
| the whole paper fails (`PaperFailure`) | no field event at all: `return EventPlan((), _paper_event(outcome, event_type="extraction_failed", …))` | **every old claim stays live** |

`live` is every live claim-bearing event of the arm on the paper, of all three claim types
(`live_claim_events(conn, outcome.paper_id, outcome.arm)` in `write_extraction_events`), so an old
`declined` or `contract_unmet` is superseded like an old value, and is left live like one.

Supersession is decided per cell, never per paper. No code compares the new record's text with the
text of claims on other cells.

Where a field becomes incomplete: `legacy_record` — a name that is neither duplicated, nor an
offender, nor in the spans ("`else: incomplete.append(name)`"); `elicited_record` — a name whose
state is none of the three tokens. The record with its incomplete list is what an exhausted
completeness budget stores: `outcome_for_exception` returns `exc.record` for
`IncompleteExtractionError` / `UncitedValueError`.

```python

        if key in _live_reuse_keys(conn, paper_id, arm):

```

The set holds the key of every live claim of the arm on the paper, across all fields. The test is
membership of the **current text's** key. So:

- **A paper whose live claims carry two keys, one of them the current text's:** skipped. One
  new-text claim on any field is enough; the old-text claims on other fields are not looked at.
- **A paper whose live claims carry two keys, neither the current text's** (a third parse):
  selected and re-extracted.
- **A paper whose live claims all carry an old key** (the failed-re-extraction case): selected again
  on every run until an extraction succeeds.

**I2: confirmed.**

## Q3. What the reader returns for a cell whose only live claim is an old-text claim — READ

`effective_value`: the cell has one live claim, no reviewer event, and **no `superseded` event on
that cell**, so `superseded` (computed over the cell's own events) is empty and the row-9 keys are
not added. The value comes from `_classify_claim`:

```python
    cites = _citations_for(evs, ev.claim_id)
    state = classify_field_state(ev.value, cites, ev.event_type, sentinels=sentinels)
    ...
    if located is not None:                                        # rows 10 / 12
        return EffectiveValue(ev.value, state, 12 if is_sentinel else 10,
                              {"located": located})
    last = cites[-1] if cites else None                            # rows 11 / 13
    return EffectiveValue(
        ev.value, state, 13 if is_sentinel else 11,
        {"snippet_supplied": bool(ev.source_snippet), "located": last})
```

- **State and row:** `asserted with evidence` (row 10 or 12) if the old claim was located before,
  else `asserted without locatable evidence` (row 11 or 13); `declined` (14) or `contract unmet`
  (15) for those types. Exactly what a first-extraction claim gets.
- **Provenance:** `arm`, `claim_id`, `actor`, `role`, plus `located` (the `citation_located`
  payload, which does carry `parsed_text_sha256` / `parsed_text_uid` of the text the locator
  checked) or `snippet_supplied`. **The claim's own text identity is not exposed**: the claim
  event's payload keys (`reuse_key`, `parsed_text_sha256`, `parsed_text_uid`) are not copied into
  the provenance, and nothing compares them with the paper's current text or with the other cells.
- **The grid** (`iter_grid`) yields the cell like any other.
- **Evidence table** (`engine/exporters/evidence_table.py`): the row emits `ev.value`, the located
  snippet, `ev.state` and `ev.rule_row` per field, and the paper-level `state.processing`,
  `state.processing_reason`, `state.analysis_ready`. The stale cell appears as a normal value with a
  normal state and row. A paper whose re-extraction failed is exported with `extraction_failed` in
  its processing column **and** its old-text values in the field columns (`has_data` is "a cell the
  store has a RECORD for").
- **Concordance** (`load_arm`): reads the same grid through the reader; I read its docstring and
  imports only ("Load extracted values for an arm, THROUGH THE READER"), not its filtering, so what
  it does with a failed paper's cells is not stated here.

## Q4. Intent — READ (plan and addendum 3, verbatim)

- **R140:** "A paper stores what the arm produced. extraction_failed is reserved for outcomes where
  the arm produced nothing usable and the paper should be retried next run (F9 set). Fields missing
  after the completeness budget get no field event and are listed in the extracted paper event's
  payload.incomplete_fields (reader row 1); the paper is not failed. Exhausted response_unparseable
  and no_fields_returned are extraction_failed."
- **Rule v2.1 row 1:** "**Missing** | assigned; no `field_events` row | — | **missing** | `{arm,
  reason: "assigned, no claim"}`".
- **Rule v2.1 row 9:** "**Superseded within one arm** (R10, R21) | ≥2 claims with **distinguishable
  configurations**, the newer from a re-extraction whose **input identity changed** (S3d); no
  reviewer event | newest claim's value, then 10–15 | per 10–15 | `{supersedes: […],
  superseded_because: "input identity changed"}`."
- **S3d:** "Extraction reuse key. `(paper_id, parsed_text_hash, codebook_hash, prompt_hash,
  model_digest, options_hash)`. A changed input re-extracts; the previous extraction is superseded
  by an event (S2), never deleted."
- **S5b:** "Field state vocabulary, stored, scored and exported distinctly: asserted with evidence ·
  asserted without locatable evidence · declined · contract unmet · missing · unresolved (duplicate
  or needs re-review) · corrected by human · withdrawn." And R13: "'Missing' means assigned and
  absent."

**Agreement and conflict.**

- R140 and row 1 are built as written: a missing field writes no event. **I1: confirmed.**
- R140 says a missing field reads at "reader row 1". That holds only on a cell with no earlier
  claim. On a re-extraction the cell already holds the old claim, so it reads at rows 10–15 with the
  old value, not row 1. R140's text does not consider a cell that already has a claim.
- S3d says "the previous **extraction** is superseded". The build supersedes the previous **claims,
  cell by cell**, and only where the new extraction has an outcome. For a complete re-extraction the
  two are the same thing. For an incomplete or failed one they differ: part or all of the previous
  extraction stays live.
- Row 9 describes two claims on one cell. It says nothing about a cell that received no new claim
  when its paper was re-extracted, so the rule neither covers nor forbids the stale cell.

So no built rule contradicts its own ruling. The gap is between R140 and S3d, which were never
reconciled for a re-extraction, and the rule table has no row for the result.

## Q5. Every path to the state — READ

"The state": a live claim of the arm on a paper, extracted from a text that is not the paper's
current text, with no further extraction that will supersede it, or with one pending.

| # | path | what stays live | does a later run repair it? | Run 7 launch |
|---|---|---|---|---|
| P1 | Re-parse, then a re-extraction that stores with **incomplete fields** (the row) | old claims on the incomplete fields | **No** — selection skips the paper on the new key | **No**: needs earlier claims and a new text version |
| P2 | Re-parse, then the paper **fails** in the loop (`PaperFailure`: `no_fields_returned`, `response_unparseable`, `model_call_failed`, input-fit, …) | **all** old claims, every field | Only when a later extraction succeeds; until then every run re-selects it and the reader returns the old values | **No** |
| P3 | Re-parse, then the paper is **refused at selection** (D21: `record_selection_refusals` writes `PaperFailure(pid, selection.arm, run_id, reason_code, "extract_pass1", detail={"refused_at": "selection"})`) — the new version's file is missing or altered | **all** old claims | As P2 | **No** |
| P4 | Re-parse with **no extraction run after it** | all old claims; the paper's processing state still says `extracted` or `audited_ai` | By the next extraction run | **No** |
| P5 | A run **aborted or interrupted** part-way through a paper | not a path: a paper's events are one savepoint ("one savepoint, every event written with `commit=False`, one commit"), and an interrupted paper "keeps no claim and no event (E-DEADKI)" | n/a | n/a |
| P6 | **Byte-identical re-parse** | old claims under the old uid, same sha256 and key | not stale in content; selection skips correctly | **No** |

P2 and P3 answer the brief's question directly: **yes, the old claims stay live** when D21 or the
loop writes `extraction_failed`. The paper then shows `extraction_failed` on the processing axis
while every cell still resolves to an old-text value.

P4 is the state D23 was opened on, seen from the reader's side instead of the auditor's.

**I3: confirmed.** Run 7's launch is the first claim-bearing run on live (0 field events, 0

## Q6. Interaction with D23's refusal — READ (`audit_run` at `40ec8b6`)

`claim_text_ref` refuses when the claims **to locate** span more than one sha256. `todo` is live
`asserted` claims with no `citation_located` yet. So for a paper in P1's state:

| the stale old-text claim is… | audit does | result |
|---|---|---|
| `asserted`, never located | `todo` spans two sha256 → paper refused, `claims_span_text_versions` | no citation, no `audited_ai`; **and the paper is refused on every later audit too**, since selection never re-extracts it |
| `asserted`, already located by an earlier audit | it is in `done`, not `todo`; `todo` is one sha256 | audit proceeds; the paper gets `audited_ai`; the stale claim keeps its old citation and reads `asserted with evidence` |
| `declined` or `contract_unmet` | never in `claims` (asserted only) | audit proceeds; `audited_ai` |

**I4: partly contradicted.** The refusal covers the first row only. In the other two the paper is
audited and marked complete with a stale claim live. In all three the stale claim stays live in the
reader, as I4 says.

**PRISMA and the processing axis.**

- First row: the re-extraction wrote `extracted`; audit writes nothing. Processing stays
  `extracted`, which PRISMA counts as `extraction_in_progress`
  (`_EXTRACTION_IN_PROGRESS = (NO_RECORDED_STATE, "parsed", "extracted")`) and which is
  `analysis_ready` (`COMPLETED_PROCESSING_STATES = ("extracted", "audited_ai")`). It stays there
  permanently: this is D22's "audit could not run" state, and under 12d-D23-R1 R-1 it becomes

- Other two rows: `audited_ai`, counted in `studies_included`.
- P2 / P3: `extraction_failed` with its reason, counted in PRISMA's failure box, not analysis-ready,
  while the evidence table still prints the old values for the paper (Q3).

## Classification

Depends on the design; the candidates span all three.

- **(i)** if the fix is in what the extraction writes or what selection selects, using
  `superseded` as it exists (designs A, B, C).
- **(ii)** if the reader decides staleness, since that changes the resolution rule and
  `RULE_VERSION`; or if a new field state or event type names the stale cell (design D, and B if
  "superseded with no replacement" needs its own state).
- **(iii)** only if a stale or superseded-without-replacement cell must be a new stored token in a
  CHECKed vocabulary. `field_events.event_type` is CHECKed to ten types (MEASURED, DDL at 12d-OPEN);
  a new type is a schema change.

## Findings beyond the questions

- **F1 — D24 is wider than its row** (READ; Q5 P2, P3). A re-extraction that fails, or a paper
  refused at selection, leaves every old-text claim live while the paper reads `extraction_failed`.
  The evidence table then prints old-text values for a paper whose processing column says it failed.
  Whether to widen D24's row text or open a sibling is the architect's call; not chased.
- **F2 — a P1 paper with an unlocated stale claim is refused by audit permanently** (READ; Q6). The
  only exit is a new parse (a third key). After 023 this becomes a permanent `audit_not_possible`.
  Bears on R-1's reason vocabulary ("the paper's live claims spanning more than one text version").
- **F3 — R140's "reader row 1" is true only for a cell with no earlier claim** (READ; Q4). On a
  re-extraction the incomplete field reads at rows 10–15 with the old value. A statement in a
  ruling that the built reader does not satisfy in this case; for the 12d-CLOSE record.
- **F4 — the reader exposes no text identity for a claim** (READ; Q3). `effective_value`'s
  provenance carries the citation's text identity when a citation exists, never the claim's own.
  Any consumer that wants to know which text a value came from must read `claim_inputs` itself.
  Relevant to design D and to the junior audit screen; not a defect by itself.
- **F5 — `load_arm`'s treatment of a failed paper's cells was not read** (Q3). Stated as a gap in
  this report, not a finding about the code.
