## 2. The design as built (READ, `tests/conftest.py`)

### 2.1 Every test gets its own lock path

`experiment_lock_for_tests` (`:449`), autouse. For a test with no live-tier marker it sets `OLLAMA_EXPERIMENT_LOCK` to `<tmp_path>/ollama_experiment.lock` (`:453`). The file is created only if the test acquires the lock. A test that sets the variable itself (the three lock test files) or patches `hold_experiment_lock` (five files) overrides it as before.

### 2.2 The Ollama fence

`block_ollama_calls` (`:384`), autouse. It is off only for a test that carries the `ollama` marker while the opt-in is set (`:386`). Otherwise it wraps four boundaries (`:434-438`):

| Boundary | Covers | Route named in the refusal |
| --- | --- | --- |
| `httpx.HTTPTransport.handle_request`, `httpx.AsyncHTTPTransport.handle_async_request` | `ollama.Client`, the module-level `ollama.ps()`, every bare `httpx.get` | `httpx transport` |
| `requests.adapters.HTTPAdapter.send` | `requests` | `requests` |
| `socket.socket.connect`, `.connect_ex` | urllib, `http.client`, a raw socket; the backstop under the two above | `socket.connect` |

A refused request raises `OllamaCallBlocked` (`:308`), a `BaseException`, naming the test's node id, the route and the request. Each refusal is also recorded and re-asserted at teardown, so a test that swallows it still fails (as the service fence does).

**The fenced host set** — `ollama_endpoints()` (`:351`), evaluated at each request:

| Member | Source | Value on this box |
| --- | --- | --- |
| `OLLAMA_HOST`, resolved by the client library's own `ollama._client._parse_host` | environment | unset → `127.0.0.1:11434` |
| the engine client's bound host | `ollama_client._client_host()` | `127.0.0.1:11434` |
| the addresses the engine names outright | `ollama_client.OLLAMA_BASE_URL`, `ollama_client._LOCAL_SERVICE_HOSTS` | `localhost:11434`, `127.0.0.1:11434` |
| the second server (R626(c)) | `analysis.eval.qualgap01.DEFAULT_HOST` | `127.0.0.1:11435` |

Hosts are compared after normalisation (`_endpoint`, `:337`): `localhost`, `127.0.0.1`, `::1`, `0.0.0.0` and `::` are one host. So the set on this box is loopback:11434 and loopback:11435. Every member is imported from the code that owns it; the conftest carries no port literal.

A fake client put in `ollama_client._client`'s place never reaches a transport and is untouched.

### 2.3 The live-tier opt-in

`EVIDENCE_ENGINE_LIVE_TIERS=1` (`LIVE_TIERS_ENV`, `:303`). The tiers are `ollama`, `network`, `integration` (`:304`).

- **Without it:** `pytest_collection_modifyitems` (`:326`) adds a skip marker to every live-tier item, with the reason `live tier (<markers>): set EVIDENCE_ENGINE_LIVE_TIERS=1 to run it`. This applies however the test was selected: by `-m`, by file or by node id. The lock fixture repeats the skip as a backstop.
- **With it:** `experiment_lock_for_tests` leaves `OLLAMA_EXPERIMENT_LOCK` as the environment has it and holds the lock for the test through `hold_experiment_lock(blocking=False)` (`:465`). On `BlockingIOError` the test skips: `the experiment lock is held by another process (<path>); a live-tier test does not run beside it`.
- The lock is taken in-process, through the engine's own function. No second descriptor, no `flock(1)` (INT-g12-7). A blocking acquire inside the test is therefore a nested acquire and returns at once.
- Under the opt-in, a `network`- or `integration`-marked test without the `ollama` marker is still fenced from Ollama.

### 2.4 The one existing test changed

`tests/test_ollama_preflight.py::TestRequirePreflight::test_raises_on_failure` now patches `engine.utils.ollama_preflight.ollama.ps` with `{"models": []}`, as the sibling at `:236` does. Its assertion is unchanged: `require_preflight` raises `RuntimeError` matching "pre-flight check failed".

## 8. PROPOSED — CLAUDE.md text for the opt-in (not applied; for commit 5)

In "Ops Invariants — Ollama service safety", after the suite-fence bullet:

> - **The suite and the experiment lock** (`tests/conftest.py`, U12). Every test gets its own lock path under `tmp_path`; no test takes `~/.ollama_experiment.lock`.
> - **Ollama fence** (`tests/conftest.py`, U12). A request to the Ollama server from a test is refused with `OllamaCallBlocked` (a `BaseException`) at the httpx transport, the `requests` adapter and `socket.connect`. The server is `OLLAMA_HOST` as the client resolves it, the engine client's host, the addresses the engine names, and port 11435 on loopback. Only a test marked `ollama`, run with the opt-in, is exempt.
> - **The live tiers are opt-in.** Tests marked `ollama`, `network` or `integration` skip unless `EVIDENCE_ENGINE_LIVE_TIERS=1`, however they are selected. Under it each holds the experiment lock non-blocking for its duration and skips if another process holds it. No scheduled run sets it; a live-tier run is a pre-tag step.

In "Running", replacing the three test-suite lines' comments:

> ```bash
> python -m pytest tests/ -v -m "not network and not ollama and not integration"  # standard gate (and the nightly)
> EVIDENCE_ENGINE_LIVE_TIERS=1 python -m pytest tests/ -v -m "network or ollama or integration"  # live tiers: calls models and APIs, holds the experiment lock
> ```

The existing fence paragraph's sentence "No tier is exempt, including the nightly full-suite run" and the conftest docstring's reference to the nightly running with no marker filter both need rewording when commit 5 lands.
