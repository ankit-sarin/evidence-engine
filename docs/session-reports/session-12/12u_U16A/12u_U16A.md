## §2 R624(b): the changed-text cases

### 2a What the code does (anchors in `anchors_u16a.txt`)

**The reuse key** is "`(arm, paper_id, parsed_text_sha256)`" (`engine/core/reuse_key.py`). A new
`parsed_text_refs` row changes the key **only if its bytes differ**. A byte-identical re-parse has a
new uid and the same key. I2's inferred "a new reuse key" holds for case (ii) with new bytes only.

**Selection** (`engine/core/selection.py::select_for_extraction`) resolves the paper's newest version
("`ORDER BY parsed_text_version DESC LIMIT 1`"). It decides "held" from the recorded hash before it
reads the file: "`held = reuse_key(arm, paper_id, ref.sha256) in _live_reuse_keys(conn, paper_id, arm)`".
It then reads the file (`read_parsed_bytes`, which raises on "`if observed != ref.sha256:`" or
on a missing file):
- **Held paper, unreadable file:** reported, not refused ("`unreadable.append((paper_id, exc.reason_code, ref.stored_path))`").
- **Unheld paper, unreadable file:** refused ("`skipped_refused.append((paper_id, exc.reason_code))`").

**Refusal events** (`extractor.record_selection_refusals`): once per reason ("`if (state.processing, state.processing_reason) == ("extraction_failed", reason_code):`" → none written). Held-unreadable
papers get no event; they are written to run telemetry ("`kind="claimed_papers_text_unreadable",`")
and logged.

**The extract loop** (`extractor._extract_selected`) re-reads each selected paper ("`paper_text = read_parsed_text(ref)`"). On a refusal it calls "`record_failure(pid, exc, "extract_pass1")`",
unconditionally (U11 F2). Only papers selection chose reach this read, so a held paper never does.

**D24** (`engine/core/extraction_events.py`): a failed paper supersedes under its current
reference ("`current_text = resolve_parsed_text(conn, outcome.paper_id)`"), comparing each live
claim's payload key ("`if ev.payload.get(PAYLOAD_REUSE_KEY) != key}`"). With no ref row there is
no key and nothing is superseded ("`if key is None:`", R458).

**The audit** (`audit_events.audit_run`) acts only on live `asserted` claims with no
`citation_located` event. An already-audited paper has nothing to do and its file is **never
read**. Otherwise it reads the version the claims name ("`return resolve_parsed_text_by_uid(conn, uids[0])`"),
verified by hash, and on a refusal logs "`Paper %d: audit skipped — %s; parsed text uid(s) %s (%s)`"
and writes nothing (D23; no event until 023, D22). U15's state gate ("`if processing not in AUDIT_ADMITTED_STATES:`") precedes the text read.

**Who writes parsed text.** The parser writes each version to its own file ("`md_filename = f"{paper_id}_v{version}.md"`") and refuses an existing target ("A parse never overwrites a
file"). The entry importer places with "`os.link(tmp, md_path)`", which never clobbers. **No
production path writes changed bytes under an existing reference.** Cases (i) and (iii) arise only
from outside the engine (a hand edit, a deletion, a restore that does not match). Case (ii) arises
from:
- `reparse_papers`, which has no caller in `engine`, `scripts` or `analysis` (only tests), so it is
  reached from a Python call; or
- the parse stage on a changed PDF. That stage selects "`db.get_papers_by_status("PDF_ACQUIRED")`",
  which corpus papers no longer are.

**Live today** (`live_reading.txt`): `field_events 0`, `claim_inputs 0`, 194 refs all with sha256,
selection `190 0 0`. No paper is held by any arm, so no held-paper case can arise on live before
Run 7 extracts.

after an audit stage that audits at least one other. The production paths to that state:

1. **R624(b)'s cases (i) and (iii) leave a paper `audited_ai`, analysis-ready and counted in

   byte-identical re-parse is held (paper 16). R624(b)'s open question is therefore (i) and (iii)

3. **The in-loop refusal of a new version discards the arm's claims on the intact old version.**

   superseded, though v1's file verifies; the paper leaves `studies_included`. This is D24 as ruled
   ("a failed paper takes K from its current parsed_text_refs row", R455), measured here. Reported,
   not a defect claim. Rests on "`current_text = resolve_parsed_text(conn, outcome.paper_id)`".
4. **U16's acceptance test, as written, does not say what an extracted paper with nothing to audit
   does.** An all-declined paper is skipped by `audit_run` with no log line and no `AuditReport`

   "`claims = live_claim_events(conn, pid, arm, event_types=("asserted",))`" → `continue`, measured
   in `u16_declined` (`"warnings": []`). Reachable only when elicited.
5. **P1A's note gives "an interrupted audit" as U16's trigger. Code order does not support it.**
   Rests on `results["audit"] = _stage_audit(…)` followed by `_advance_extraction_workflow(db._conn)`

6. **The workflow advance's failures are swallowed.** "`except Exception:`" / "`pass  # workflow table may not exist`" (two lines). A shortfall U16 records would be lost the same way if the write raised.
7. **A held paper whose text changed before its audit is refused by the audit on every run and
   reported at selection on every later run** (papers 17, 18), with no event until 023 (D22),
