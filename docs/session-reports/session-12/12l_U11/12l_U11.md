# 12l-U11 — a missing or changed text file on an extracted paper is reported, not re-failed each run (INT-i12-69)

P1 unit U11 under R612 and R607(c). Selection-side; nothing sent changes; not pin-affecting. No model call, no live write. Written from the tree at `af9a46b` (item 0, R623).

## I1, I2

- **I1 holds.** `engine/core/reuse_key.py`: `def reuse_key(arm_id: str, paper_id: int, parsed_text_sha256: str) -> str`. Selection calls it as `reuse_key(arm, paper_id, ref.sha256)`, and `ref` comes from `parsed_text.resolve_parsed_text`, which reads one row of `parsed_text_refs` (`SELECT parsed_text_uid, paper_id, parsed_text_path, parsed_text_version, parsed_text_sha256 … ORDER BY parsed_text_version DESC LIMIT 1`) and opens no file. The file is read, and its hash compared with the recorded one, only by `read_parsed_bytes`. So the key needs the recorded hash and nothing from the file.
- **I2, where the entry is carried and logged.**
  1. `SelectionResult.claimed_text_unreadable` — `(paper_id, reason_code, stored path)` per paper, from `select_for_extraction`.
  2. A warning at selection (`engine.core.selection`), naming the paper, the arm, the condition and the path, and what clears it.
  3. `extractor.record_selection_refusals`, which every run that selects passes through: a warning for the run, and one row in the run's telemetry (`telemetry/run_events.jsonl`, kind `claimed_papers_text_unreadable`, payload `{run_id, arm, papers: [{paper_id, condition, path}]}`).
  4. The run summary: `extraction_events.run_extraction_summary(conn, run_id, selection)` returns `claimed_text_unreadable` (the same list of dicts), which `_extract_selected` puts in the run's stats.
  `condition` is the parsed-text reason code: `parsed_text_missing` or `parsed_text_modified`. One limit is F1 below.

## What changed

- **`engine/core/selection.py::select_for_extraction`**: resolve the reference; build the key and ask whether the arm holds it; then read the file. An unreadable file on a held paper puts the paper in `skipped_asserted` and in `claimed_text_unreadable`; on a paper the arm does not hold it is `skipped_refused`, as before. A paper with no recorded text at all is refused as before. `bound_selection` carries the new field.
- **`engine/agents/extractor.py::record_selection_refusals`**: a refusal event is written only when the paper's processing state is not already `extraction_failed` with that reason code (`effective_state(conn, pid)`); it returns the number written. It writes the telemetry row and the warning for the held papers.
- **`engine/core/extraction_events.py`**: `claimed_text_unreadable_entries(selection)` and the `selection` argument of `run_extraction_summary`.

A held paper gets no event of any kind: its processing state, its claims and its D24 supersession are untouched.

## R509 findings (none Class 1)

- **F1 — when nothing is selected, `run_pipeline`'s extract stage returns its own stats and they do not carry the new entry.** `scripts/run_pipeline.py::_stage_extract`, on `if not selection.to_extract:`, builds `{"extracted": 0, "skipped_asserted": …, "skipped_refused": …}` and returns before `run_extraction`, so `run_extraction_summary` is not reached. That is the usual shape of the case this unit is about (every paper already extracted). The condition is still logged twice and written to the run's telemetry on that path; only the returned stats lack it. `run_pipeline.py` is outside this unit. Proposed Class 3, P1 or P7: that return takes the summary's entry.
- **F2 — the in-loop text refusal still writes an event each time.** `_extract_selected` re-reads the file (`read_parsed_text(ref)`, R95) and, if it changed between selection and the read, calls `record_failure(pid, exc, "extract_pass1")` unconditionally. The window is one run, and the next run's selection applies the once-only rule, so a repeat needs the file to change in that window on successive runs. Proposed: no row, or a note on INT-i12-69.
- **F3 — a held paper whose text changed is not re-extracted, and nothing but the report says its claims rest on bytes that are no longer on disk.** This is the contract ("re-extracting a paper whose text changed" is out of scope). The paper stays `audited_ai`; the audit's own refusal of the same file is `audit_events.py`'s. Proposed: a note on INT-i12-69 for the audit-side unit.
- **F4 — `skipped_asserted` now counts papers whose file was not readable.** Readers of that count (`run_pipeline`'s "Nothing to extract" line, the stats) see such a paper as an ordinary skip; the separate entry is what distinguishes it. No row proposed.
