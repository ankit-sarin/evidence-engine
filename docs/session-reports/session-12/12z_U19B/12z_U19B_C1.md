## §6 Findings

- **F1. The check runs only after a performed restart.** `restart_ollama -> bool` returns True after a performed restart and False on a skip. S9 calls `_recheck_env_after_restart` only when it is true, outside S9's `try`. A failed restart still continues the run (R734(c)(iv)), while a drift read stops it.
- **F2. The open read has no gate role.** It records the raw string and gates nothing: a read failure records `""`, and the stage-start check (S5–S7, unchanged) fails the run as before.
- **F3. The commit adds 14 ids, not 13.** The fourteenth is generated: `test_api_parity` parametrizes over every engine import in `scripts/`, so run_pipeline's new module import adds one id. It is green, it is not a hand-written acceptance id, and it is reported as new.
- **F4. The CLAUDE.md placement departs from R734(d)(iii)'s literal text.** R734(d)(iii) names "CLAUDE.md's `open_run` refusal list" for both classes, but `ServerEnvChanged` is raised by the extract loop, not at `open_run`. Adding it to the open-time list would misstate the code. CLAUDE.md therefore names it in the same paragraph, beside `ModelDigestChanged`'s per-call sentence (the paragraph's other run-time refusal): "After a performed proactive restart, a correctness-tier drift in the re-read environment raises `ServerEnvChanged`, which `run_pipeline` closes 'aborted' (U19, R734(c))." This is a departure the code forced.
- **F5. One rewritten test keeps an inaccurate name.** `test_skip_returns_none_and_does_not_raise` asserts `is False` now; it keeps its name so that its id does not change against the reference.
