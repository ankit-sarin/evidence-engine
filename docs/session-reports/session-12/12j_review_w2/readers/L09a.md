### L09a-C1 — the xlsx importers' header fallback reads the MODEL's "Primary Decision" column as the human decision
- **File / function:** `screening_adjudicator.py::_import_abstract_xlsx` and `ft_screening_adjudicator.py::_import_ft_xlsx` — the nested `_find_col`, identical in both.
- **Pattern:** vi / other
- **Evidence level:** reproduced
- **Evidence:**
  ```python
  def _find_col(candidates: list[str]) -> int | None:
      for c in candidates:
          for header, idx in col_index.items():
              if c.lower() in header.lower():
                  return idx
  ...
  decision_col = _find_col(["PI_decision", "DECISION"])
  ```
  The match is a case-insensitive SUBSTRING, walked in column order. When no header contains
  `PI_decision`, the fallback `"DECISION"` matches the first header containing "decision" — and both
  exporters put `Primary Decision` (and `Verifier Decision`) to the LEFT of the human column.
  Its values pass validation: abstract `str(decision_raw).strip().upper()` turns the model's
  `include`/`exclude` into `INCLUDE`/`EXCLUDE`; FT's primary on a verifier-flagged paper is `FT_ELIGIBLE`.
  `L09a_1_abstract_import.py` (b): headers `…, Primary Decision, Verifier Decision, DECISION`, human
  wrote EXCLUDE ×3 → `IMPORT SUCCESSFUL — 3 decisions`, `include: 3`, all three `ABSTRACT_SCREENED_IN`,
  stage completed. `L09a_2_ft_import.py` (a): human wrote FT_SCREENED_OUT ×3 → `ft_eligible: 3`, all
  `FT_ELIGIBLE`, three `adjudicated → eligible` events under an `import` manifest (actor human / reviewer).
- **What goes wrong:** a workbook whose human column is headed `DECISION` / `Decision` (the very shape the
  fallback exists for — CLAUDE.md: "Passing an `.xlsx` path imports an archival workbook") or whose
  `PI_decision` header was edited has every paper adjudicated by the model's own primary decision,
  recorded as a human decision, with a success message. In FT that is a wholesale `eligible` — the
  corpus — signed "human".
- **Refutation tried:** the current exporters always write `PI_decision (…)`, so a round-trip of an
  untouched export is safe; the trigger is a legacy/hand-built/renamed header. No ruling found
  (`_find_col` / `PI_decision`: 0 hits in the plan and in 12f triage). Same substring rule also
  resolves `Title`, `Paper ID`, `Reason`, `Notes`, `Row` — no collision found for those with the current headers.
- **Tests:** every xlsx import test (`tests/test_adjudication.py::test_import_decisions` and siblings,
  `tests/test_ft_adjudication_import.py::test_11_…_in_xlsx`, `tests/test_ft_screening.py` import tests)
  fills the exporter's own workbook by column number; none presents a `DECISION` header, so the fallback
  branch is never run.
- **Existing row:** new
- **Proposed class / package:** 1 (conditional: a workbook without a `PI_decision` header) / P4 — a human gate records the model's answer as the human's.
