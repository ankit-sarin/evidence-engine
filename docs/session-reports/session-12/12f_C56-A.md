Per fault class at this handler:

| fault | outcome | counts toward the 3-in-a-row `RunAborted`? |
|---|---|---|
| `UndeclaredCall` | re-raised → #2 closes `failed` | — |
| `EventRefused`, `CodebookContractError`, `ExhaustedWithoutRecord`, `RunAborted` | re-raised | — |
| `UndeclaredOverride` | **not in the tuple** → `extraction_failed` / `unclassified_error`. No raising site inside this `try` today | yes |
| `RunRefused` family | **not in the tuple** → `unclassified_error`. No raising site inside this `try` today (`verify_extraction_run` runs before the loop) | yes |
| recorder `sqlite3.Error`, and any other `sqlite3.Error` that is not an `EventRefused` | `extraction_failed` / `unclassified_error`; the paper event is then written on the same connection (if that write fails too, it raises out of the handler) | yes |
| `TimeoutError`, httpx, `ollama.*` | `extraction_failed` / `model_call_failed` — the declared F9 mapping (the docstring's R5) | yes |
| `CeilingUnavailable` | `extraction_failed` / `context_ceiling_unavailable` (and see N1) | yes |
| `InputOverflow` / `InputTruncated` / `InputDropped` | `input_exceeds_context` — a property of the paper's input, by design | no |
| `RunInterrupted`, `KeyboardInterrupt` | pass through (`BaseException`) | — |

So the conversion is bounded, not unbounded: a machine-level fault writes at most three consecutive
`extraction_failed` events before `RunAborted` stops the run, and such papers hold no live claim, so a
later run selects them again. The unbounded case is an **intermittent** fault (it resets the counter at
every success): each affected paper is recorded as failed by its own doing and the run closes `completed`.

**One shared fix shape.** There is no single exported "run fault" tuple today: `outcome_for_exception` holds the list inline
(`CodebookContractError, ExhaustedWithoutRecord, EventRefused, RunAborted, UndeclaredCall`) and `parse_all_pdfs` adds
`FileExistsError` by its own clause. `UndeclaredOverride` and `sqlite3.Error` are on neither list. One predicate, owned in
one module and imported by the parser, the cloud loops and the extractor, is the smallest change that keeps the sites agreed.

   paper failures on the extract path; the C56 row lists all of them as swallowed by `_retry_snippet`.
