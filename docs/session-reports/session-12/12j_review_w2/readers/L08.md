### L08-C1 — An interrupt mid-import is not handled; in-process, the half-written import stays open on the connection and the next workflow read commits it

- **File / function:** `engine/adjudication/import_extraction_entry.py::import_extraction_entry`;
  `engine/adjudication/import_screening_entry.py::import_screening_entry` (same shape);
  committed by `engine/adjudication/workflow.py::ensure_workflow_table`.
- **Pattern:** iii (also i)
- **Evidence level:** reproduced
- **Evidence:** both importers guard their unit of work with `Exception` only:
  ```python
          conn.commit()
      except Exception as exc:
          conn.rollback()
          for path in reversed(placed):
              path.unlink(missing_ok=True)
          rm.close_run(conn, run_id, "aborted" if refused else "failed",
                       reason=refused or loop_reason or str(exc))
          raise
  ```
  `KeyboardInterrupt` and `rm.RunInterrupted` are `BaseException` (`run_manifest.py`: "deliberately not
  an Exception: every `except Exception` on the run path … must let it through"), so neither the
  rollback, the unlink, nor the close runs. The documented invocation is in-process, with no CLI:
  `import_extraction_entry(ReviewDatabase(<id>), <json>, spec=load_spec_for(<id>))`. The connection then
  still holds the open transaction, and every workflow reader commits it —
  `workflow.py::ensure_workflow_table`: `conn.executescript(_WORKFLOW_STATE_TABLE)` / `conn.commit()`,
  reached from `is_stage_done`, `get_workflow_status`, `get_current_blocker`, `format_workflow_status`,
  `advance_stage`.
  Reproducer `repro/L08/L08_1_interrupt_partial_import.py` (+ `.out`), KeyboardInterrupt at entry 2 of 3:
  ```
  [after interrupt, same connection] in_transaction=True papers=2 paper_events=1 refs=2 files=['1_v1.md', '2_v1.md'] manifests=[(1, 'import', None)] stages_complete=0
  committed papers seen by a second read-only connection: []
  -> get_workflow_status(conn)
  [after the read] in_transaction=False papers=2 ...
  committed papers seen by a second read-only connection: [(1, 'FT_ELIGIBLE'), (2, 'FT_ELIGIBLE')]
  eligible_paper_ids (what extraction selects from): [1]
  retry: ExtractionEntryRejected … holds 2 papers row(s) (R-e) … parsed_text is not empty (R-l)
  ```
  Screening entry, interrupt at entry 3 of 3: after `get_workflow_status`, a second connection sees
  `[(1, 'INGESTED'), (2, 'INGESTED')]`, manifest `(1, 'import', None)`.
- **What goes wrong:** Ctrl-C (or SIGTERM under `interrupt_signals`) during an import called from a
  REPL / notebook / long-lived script leaves a partial corpus uncommitted on the connection; the first
  workflow status or gate check on that `ReviewDatabase` (or any other committing call) makes it
  durable: a truncated corpus (N of M papers), one paper at `FT_ELIGIBLE` with a ref but no `eligible`
  event, the eight screening stages still pending, under a manifest that never closes. For the
  screening entry the result is a silently truncated citation set at INGESTED that abstract screening
  will select. The retry is refused (R-e), so the only loud signal arrives after the partial is durable,
  and nothing in the stored state says "partial" other than the open manifest. If the process exits
  instead, SQLite rolls back and the DB is clean — see C2 for what is left.
- **Refutation tried:** `ReviewDatabase.close()` only closes (no commit), so a script that dies is safe
  for the DB. Connection is default `isolation_level` (implicit transaction, no autocommit) — confirmed
  in `ReviewDatabase.__init__`. C47 (closed 2026-10-01) handled interrupts in `run_pipeline` and
  `run_ft_invocation` only; grep of the plan and of `engine/adjudication/*.py` shows no
  `BaseException`/`KeyboardInterrupt` handling in any importer and no ruling accepting it. No reader
  filters on `run_manifests.ended_at` (`grep "ended_at IS NULL"` → only the migrations' CHECKs).
- **Tests:** `test_t6a_a_generic_failure_at_entry_2_rolls_back_and_closes_failed` (both test files)
  injects `RuntimeError` only; `tests/test_run_interrupts.py` (C47's T1–T9) does not cover the imports.
- **Existing row:** extends C47 (two new sites of the closed defect, with a worse consequence because
  the write is one deferred transaction) and C37 (the reader-side commit is what makes it durable).
- **Proposed class / package:** 1 / P5 — a truncated corpus or citation set can become the stored
  review with no stored marker; condition: the import is interrupted in a process that goes on using
  the same connection.

### L08-C3 — The bypass record ("Logged to audit trail") is one mutable row; `complete_stage` and `reset_stage` erase it

- **File / function:** `workflow.py::bypass_stage`, `complete_stage`, `reset_stage`, `advance_stage`
- **Pattern:** i (iv)
- **Evidence level:** reproduced
- **Evidence:** `advance_stage`: `"message": f"Stage {stage_name} bypassed with --force. Logged to audit trail."`.
  The trail is `workflow_state.metadata` (plus a `logger.warning`). `complete_stage` overwrites
  unconditionally —
  ```python
  """UPDATE workflow_state
     SET status = 'complete', completed_at = ?, metadata = ?
     WHERE stage_name = ?"""
  ```
  — and `reset_stage` sets `status = 'pending', completed_at = NULL, metadata = NULL`. Only
  `advance_stage` checks `is_stage_done` first; the automatic completers call `complete_stage` directly
  (`screening_adjudicator.py` ×3, `ft_screening_adjudicator.py`, `screener.py`, `ft_screener.py`,
  `run_pipeline._advance_extraction_workflow`, `import_extraction_entry`).
  Reproducer `repro/L08/L08_2_bypass_record_overwritten.py` (+ `.out`):
  ```
  row: ('bypassed', 'Stage ABSTRACT_ADJUDICATION_COMPLETE bypassed by operator at … Note: skip the human review')
  after a later complete_stage: ('complete', 'import complete')
  rows anywhere still saying 'bypassed': 0
  after reset_stage: ('pending', None, None)
  ```
- **What goes wrong:** a human gate is force-bypassed, downstream stages run (parse, extraction), then
  any later automatic completion of that stage rewrites the row to `complete`. The database no longer
  records that work proceeded past a bypassed gate; the same holds for the timestamp and note of an
  earlier legitimate completion (each re-run of screening or `run_pipeline` rewrites `completed_at`).
  `workflow_state` has no history table and writes no `paper_events` / manifest.
- **Refutation tried:** grepped the plan for `bypass_stage` (one hit, inside C-row text about the audit
  stages, no ruling on the record's durability) and `reset_stage` (none). `reset_stage` has no engine or
  script caller (tests only), so the erase-by-reset half is latent.
- **Tests:** `test_bypass_stage`, `test_advance_stage_force`, `test_format_workflow_status_bypassed`
  assert the row immediately after the bypass; none completes the stage afterwards.
  `test_reset_stage` pins the erase.
- **Existing row:** new (A6's family: relational state updated in place outside the event store).
- **Proposed class / package:** 1 / P2 — the stored record of a human gate goes silent about a bypass;
  lower to 3 if the log line is ruled to be the audit trail.
