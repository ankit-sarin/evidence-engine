## Summary

1. **I3 is false.** `run_stage_configs` stores the declared model per stage (`model_name TEXT NOT NULL`,
   plus `model_digest`). `active_stage_row` simply does not select it. A model check needs **no schema
   change**.
2. **No `with_model` site is class (c) today.** Three sites call it. Under an active run, two are
   reachable and always equal (the branch that calls `with_model` is not taken); one is not reachable
   inside any run. `with_model` executed **zero times** in the whole gate selection (suite).
3. **`with_model` is not the only way a caller names a model.** `stage_config(stage, spec, model=…)` is a
   second route, used by `screen_paper` and by `check_model` (preflight). Preflight does **not** go through
   `with_model` at all, so the question "must preflight stay exempt from a `with_model` guard" does not
   arise for a guard placed there — but such a guard also would not cover the route preflight and the
   abstract screener actually use.
4. **Preflight already has a non-opt-in check, by accident and after the fact.** Preflight rows are keyed
   `preflight:<model>`, one per declared model, and `run_calls` has a composite foreign key to
   `run_stage_configs(run_id, stage)`. A preflight of an undeclared model under an active run is **sent**,
   then its `run_calls` insert fails `FOREIGN KEY constraint failed`, which `check_model` reports as a model
   error (probe).
5. **Candidate row, outside C54 (probe, end to end):** `run_pipeline` started at `search` or `screen`
   cannot pass its own SCREEN stage. `_open_run_manifest` declares preflight rows for the extractor and
   audit models only; `run_screening` preflights the abstract-screening primary (`qwen3:8b` on the live
   spec), which is not declared. The probe call is sent, the foreign key refuses its record, and
   `run_screening` raises `RuntimeError: Abstract screening pre-flight check failed: qwen3:8b: FOREIGN KEY
   constraint failed`. Not acted on. See §Findings F1.

## Q1 — `with_model`, `with_options`, `active_stage_row`, and what a stage row stores

`engine/core/effective_config.py`, `EffectiveConfig.with_model`:

```python

        """A caller-named model (the preflight target, a `model=` override)."""
        return _replace(self, model=model, sources={**self.sources, "model": source})
```

No read of the active run; no refusal. (Its docstring names "the preflight target", but no preflight code
calls it — read, and suite: zero executions.)

`EffectiveConfig.with_options`, the check (same file):

```python

        row = active_stage_row(self.stage)
        if row is not None:
            recorded_hash, recorded_json = row
            if merged.options_hash != recorded_hash:
                ...
                raise UndeclaredOverride(self.stage, differing)
        return merged
```

`options_hash` excludes the model by construction (same file): `"""Every request kwarg except model,
messages and format (S3d's key)."""`.

`engine/core/run_manifest.py`, `active_stage_row`:

```python
    active = _ACTIVE.get()
    if active is None:
        return None
    conn, run_id = active
    row = conn.execute("SELECT options_hash, options_json FROM run_stage_configs "
                       "WHERE run_id = ? AND stage = ?", (run_id, stage)).fetchone()
    return None if row is None else (row[0], row[1])
```

The stored row, from the live database's `sqlite_master` (`mode=ro`):

```sql
CREATE TABLE run_stage_configs (
    run_id          INTEGER NOT NULL REFERENCES run_manifests(run_id),
    stage           TEXT    NOT NULL,
    stage_kind      TEXT    NOT NULL CHECK (stage_kind IN (...)),
    arm_name        TEXT    REFERENCES arms(arm_name),
    provider        TEXT    NOT NULL CHECK (provider IN ('ollama', 'openai', 'anthropic')),
    model_name      TEXT    NOT NULL,
    model_digest    TEXT,
    options_json    TEXT    NOT NULL,
    options_hash    TEXT    NOT NULL,
    ...
    PRIMARY KEY (run_id, stage),
    CHECK (provider IS NOT 'ollama' OR (model_digest IS NOT NULL AND length(model_digest) = 64))
)
```

and `run_calls` carries `FOREIGN KEY (run_id, stage) REFERENCES run_stage_configs(run_id, stage)`.

**Is the declared model stored per stage? Yes** — `model_name`, written by `open_run` from
`r.config.model`. **I3 is refuted**: the row has the model; only `active_stage_row`'s SELECT omits it.

Two properties of the lookup matter later:

- `active_stage_row("preflight")` returns `None` under every run (probe), because no row is ever keyed
  `preflight`; the rows are `preflight:<model>` (`resolve_run`: `out[f"preflight:{m}"] = …`). So
  `with_options` on a preflight config is silently unchecked today. No caller does that (read).
- `record_active_ollama_call` derives the same key at record time:
  `key = f"preflight:{request.get('model')}" if stage == "preflight" else stage`.

## Q3 — preflight

`check_model` (quoted in B) resolves `stage_config("preflight", spec, model=model_name)` and sends
`ollama_chat(messages=[dict(m) for m in PREFLIGHT_MESSAGES], max_retries=0, wall_timeout=60.0,
**cfg.kwargs())` inside `try: … except Exception as exc: return ModelResult(model=model_name,
status="error", …, error_message=str(exc))`. `require_preflight` raises `RuntimeError(f"{runner_name}
pre-flight check failed: {result.error_summary}. Aborting — fix model availability before retrying.")`.

The two declarations:

- extraction, `scripts/run_pipeline.py::_open_run_manifest`:

  ```python
      if any(s.startswith("extract") or s == "elicitation_pass1" for s in stages):
          preflight.append(stage_config("extract_pass1", spec).model)
      if "audit" in stages:
          preflight.append(stage_config("audit", spec).model)
      if preflight:
          stages.append("preflight")
      ...
      handle = rm.open_run(db._conn, spec, kind=kind, stages=stages, codebook=codebook,
                           preflight_models=sorted(set(preflight)), selection_bound=bound)
  ```

- screening, `engine/agents/ft_screener.py::open_screening_manifest`:

  ```python
      stages = ["ft_screen_primary", "ft_screen_verifier"]
      preflight: list[str] = []
      if with_preflight:
          stages.append("preflight")
          preflight = sorted({spec.ft_screening_models.primary,
                              spec.ft_screening_models.verifier})
  ```

Stage rows these produce (probe): pipeline from `search` — the two abstract stages, `vision_parse`, the
three extract stages, `audit`, `preflight:deepseek-r1:32b`, `preflight:gemma3:27b`; from `parse` — the
same without the abstract stages; from `extract` — without `vision_parse`; from `audit` — `audit`,
`preflight:gemma3:27b`. FT — `ft_screen_primary`, `ft_screen_verifier`, `preflight:gemma3:27b`,
`preflight:qwen3:32b`; with `with_preflight=False` (verify-only), no preflight row.

**Would a single-model equality check refuse preflight?** As `with_options` does its lookup — by the bare
stage name — it would do nothing at all: `active_stage_row("preflight")` is `None`, so a guard written that
way would **exempt preflight silently**, which is R4's failure exactly. **I5 is half right**: the stage
declares several models, but as several rows, one model each, not one row with several models.

**Must it stay exempt? No, and there is a mechanism that does not depend on the caller.** The declaration
is already per model, so the preflight form of "equal to the declared model" is "the row `preflight:<model>`
exists in this run". That is the key `record_active_ollama_call` already derives, and the foreign key
already enforces it — late. Probe P4, under the pipeline manifest:

| `check_model(…)` | result | chat calls sent |
|---|---|---|
| `gemma3:27b` (declared) | `ok` | 1 |
| `qwen3:8b` (not declared) | `error`, `FOREIGN KEY constraint failed` | 1 |
| `never-declared:1b` | `error`, `FOREIGN KEY constraint failed` | 1 |

So R63's "the stage's model is the caller's by nature" holds for *which* models a run declares
(`preflight_models` is the caller's), not for what may be sent once the run is open. The present enforcement
has three weaknesses: the call is sent (and the model loaded) before it is refused; no `run_calls` row
records the sent call; and the message tells the operator to "fix model availability" for what is an
undeclared stage.

## Q6 — remedy options (candidate wording only; nothing acted on)

None needs a schema change: `model_name` is already stored. Only a wish to *record* a refused call under a
new `run_calls.outcome` token would touch a CHECK, and that would belong in 023.

**O1 — guard `with_model`, mirroring `with_options`.** `active_stage_row` (or a sibling) also returns
`model_name`; `with_model` raises an `UndeclaredOverride`-family refusal when the active run declared the
stage with a different model.
*Cost:* small, one module plus the lookup. *Schema:* none. *Tests:* about three new (differing refused,
equal passes, no run unchanged); no existing test changes (suite).
*Limits:* covers three sites of which none is reachable with a differing model today; does **not** cover
`stage_config(model=)` — the route `screen_paper` and preflight use — so the only class (c) row stays as it
is; and a bare-stage lookup is blind to `preflight`. Also, at `parse_with_vision` the refusal would be
raised inside `parse_pdf`'s `except Exception as exc: _record_error("qwen2.5vl", exc, started)` and be
recorded as a parser failure rather than stop the run (read) — true of `with_options` there today.

**O2 — remove the caller-named model from the three sites, and `with_model` with it** (the FT-OVR
precedent, R-c: a removal, not a guard). `semantic_verify`, `audit_span`, `parse_with_vision`,
`_classify_page` lose `model=` / `vision_model=`; `parse_pdf` and `_run_parser` stop forwarding
`vision_model`; `with_model` is deleted as uncalled.
*Cost:* small to moderate; four signatures, three call shapes in `parse_pdf`, docs. *Schema:* none.
*Tests:* the `test_request_capture.py` vision call drops its argument; `test_extraction_signatures.py` to be
re-checked; request bytes unchanged (the capture instrument is the proof). *Limits:* same blind spot as O1
for `stage_config(model=)`; `screen_paper`'s `model=` (row E8) and preflight are untouched.

**O3 — check at the send boundary.** In `ollama_chat`, under an active run and with a `stage`: derive the
key as `record_active_ollama_call` does (shared, not copied), read the run's row, and refuse **before
sending** when the row is absent or its `model_name` is not the request's model.
*Cost:* moderate; one query per call on the primary key, in the one function every engine call passes
through. *Schema:* none if the refusal is raised and not recorded; a recorded outcome token is 023.
*Tests:* new tests for undeclared stage, differing model, declared preflight, undeclared preflight, no run;
no existing test changes (suite: 134 of 134 in-run sends agree; the one undeclared-preflight test patches
`ollama_chat` and is not reached).
*Why it answers R4:* nothing opts in — `with_model`, `stage_config(model=)` and a hand-built request all
arrive here — and preflight needs no exemption because its key already carries the model. It turns today's
after-the-send foreign-key failure into a before-the-send refusal with its own name. *Open points for the
ruling:* the refusal's class (an `Exception` would still be swallowed by `check_model`, `parse_pdf` and
`_classify_page`'s handlers; `ServiceCallBlocked` and `RunInterrupted` are the precedents for a
`BaseException`); and whether a run that never registered through `open_run` (the M3 test affordance)
is checked.

**O4 — O3 plus O2.** The boundary check as the control, the dead parameters removed so no site offers an
override the boundary would only refuse.

**Candidate wording for the C54 row, should it be re-scoped:** "A run sends a model its manifest did not
declare for the stage only by refusing it before the call: under an active run, `ollama_chat` refuses a
request whose stage key has no `run_stage_configs` row or names a different `model_name`."

## Findings

**F1 — candidate row (defect candidate, outside C54; not acted on).** *`run_pipeline` started at `search`
or `screen` fails at the SCREEN stage's preflight: `_open_run_manifest` declares `preflight` rows for the
extractor and audit models only, `run_screening` preflights `spec.screening_models.primary`, and the
probe's `run_calls` insert under `preflight:<that model>` violates the `(run_id, stage)` foreign key;
`check_model` reports it as a model error and `require_preflight` raises.* Established by probe S1 with
the real `_open_run_manifest(db, spec, 0)` and the real `run_screening` on a temporary review:
`RuntimeError: Abstract screening pre-flight check failed: qwen3:8b: FOREIGN KEY constraint failed.
Aborting — fix model availability before retrying.`; one chat call sent; zero `run_calls` rows. It would
not occur on a spec whose abstract primary is also its extractor or audit model. `--skip-to parse` and
later are unaffected (probe S2: every preflight those stages make is declared). Not exercised on live:
the corpus is past screening and R237 holds extraction.

**F2 — the same call omits `spec=`.** `run_screening` and `run_verification` call `require_preflight([…],
runner_name=…)` with no `spec=`, as the FT site does (row C49 names only the FT site). No wire difference
while the spec has no `preflight` block (read: `review_specs/surgical_autonomy.yaml` has none).
