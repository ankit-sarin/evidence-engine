### L13-C1 — A returned review workbook carries nothing that binds a row's decision to the paper it was exported for
- **File / function:** `engine/exporters/review_workbook.py` · `_build_review_queue_sheet`, `_build_instructions_sheet`, `create_review_workbook`
- **Pattern:** vi
- **Evidence level:** conditional (condition: the returned file's rows differ from the exported ones — a partial-column sort in Excel, a pasted or deleted row, an edited identity cell — AND the importer joins on the key alone; the importer half is outside this lot, quoted below for the call shape only)
- **Evidence:**
  - `_build_review_queue_sheet` writes context cells and decision cells the same way and sets no protection and no per-row token: `cell = ws.cell(row=row_idx, column=col_idx, value=value)` … `ws.cell(row=row_idx, column=col_num, value="")`. The sheet ends with `ws.freeze_panes = "A2"` and `ws.auto_filter.ref = …`; there is no `ws.protection`, no locked/unlocked cell style, no hidden key column, no row digest. The builder has no notion of which column is the identifier — `ColumnDef` has `key, header, width, wrap, truncate, fill` only.
  - The only record of what was exported is human-facing text on the Instructions sheet: `add_field("Total rows in Review Queue", str(config.row_count))`, `add_field("Export date", export_date)`, `add_field("Database", config.db_path)`. `row_count` is the caller's number, not `len(rows)` (repro `[e]`: sheet says 999, 2 rows written). No export id, no database fingerprint, no hash of the row set.
  - **Which identifier each workbook carries** (callers, for the record): FT queue — `ColumnDef(key="paper_id", header="Paper ID")` = `papers.id` (integer), plus `ColumnDef(key="ee_identifier", header="EE-ID")` = the stored column `papers.ee_identifier`, declared "read-only context" in `columns_importer_ignores`. Abstract queue — **no paper id column at all** (`_write_xlsx` builds rows without `paper_id` although `_collect_db_flagged` has it); the row is identified by `Title`, `DOI`, `PMID` text cells.
  - Importer side (outside lot, call shape only): `ft_screening_adjudicator._import_ft_xlsx` takes `paper_id = row[paper_id_col].value`, checks only `_is_paper_id(paper_id)`, and `_apply_ft_decisions` calls `review_db.update_status(paper_id, decision)` — the `Title` cell is stored into `ft_screening_adjudication.title` and never compared with `papers.title`. Neither importer reads the Instructions sheet's row count.
- **What goes wrong:** the PI sorts or filters one column block (the builder turns on auto-filter over all columns, so a whole-row sort is safe, but a selected-range sort or a paste is not), or a row is deleted. Decisions then sit beside other papers' ids. Every row still validates (integer id, valid decision), the import prints `IMPORT SUCCESSFUL`, and FT eligibility events are written for the wrong papers. A deleted row is not noticed either: nothing compares rows returned with rows exported.
- **Refutation tried:** looked for sheet protection, a hidden key, or a digest in the builder (none); for a content comparison in `_import_ft_xlsx` / `_apply_ft_decisions` (none — title is written, not compared); for a completeness check against the export (none; the FT gate `check_ft_adjudication_gate` only withholds stage completion while a paper is still FT_FLAGGED, which catches a missing row later but not a swapped pair). `update_status` refuses only a paper not at FT_FLAGGED, so a swap among flagged papers passes. The import manifest records the file's sha256 (`inputs={stored: file_sha256}`) — that is provenance of the file, not a check of its rows. The xlsx path is labelled deprecated (`"xlsx export is deprecated for interactive review"`), but both xlsx importers are live and CLAUDE.md states "Passing an `.xlsx` path imports an archival workbook".
- **Tests:** `tests/test_ft_adjudication_import.py` hand-builds a "Review Queue" sheet; `tests/test_adjudication.py` and `tests/test_ft_screening.py` round-trip a builder workbook in exported order. None returns a workbook whose rows were reordered or whose title disagrees with its Paper ID.
- **Existing row:** extends INT-i12-77 / R596(d) (a new site: the engine's own queue workbook, joined on `papers.id` alone for FT and on PMID→DOI→title text for abstract; neither uses `EE-{papers.id}`, and `papers.ee_identifier` travels only as ignored context)
- **Proposed class / package:** 1 (conditional) / P5 — a human gate can be written against the wrong paper silently; the builder half of the fix is a per-row token the importer checks.

### L13-C2 — DOCX "Study" label is the first author's initials for PubMed-format names, and raises on an empty first author
- **File / function:** `engine/exporters/docx_export.py` · `export_evidence_docx`
- **Pattern:** v
- **Evidence level:** reproduced for the expression (`repro/L13/L13_2_docx_label_and_chars.py`, block `[a]`); code order for the path that feeds it
- **Evidence:**
  - `study_label = f"{authors[0].split()[-1]} et al." if len(authors) > 1 else authors[0]`
  - `engine/search/pubmed.py`: `authors=rec.get("AU", []),` — MEDLINE `AU` is "Surname Initials".
  - Output: `['Smith JA', 'Jones B'] -> 'JA et al.'` · `['John A. Smith', 'B Jones'] -> 'Smith et al.'` · `['van der Berg P', 'X Y'] -> 'P et al.'` · `['', 'Jones B'] -> IndexError list index out of range`
- **What goes wrong:** every PubMed-sourced paper with more than one author is labelled by initials ("JA et al."), while an OpenAlex-sourced paper gets a surname — in the one column that identifies a row of the submission table (see C3). A first author stored as an empty or whitespace string aborts the whole DOCX with `IndexError`, after `export_all` has already replaced the PRISMA CSV, evidence CSV and evidence xlsx (F09 (d)).
- **Refutation tried:** checked whether authors are normalised on ingest (`pubmed.py` passes `AU` through; `openalex.py` appends display names); whether another exporter shares the logic (grep `split()` / `study_label` in `evidence_table.py`: no hit — it is this file only); `json.loads` failure is handled (falls to the title), a non-list or list-of-dict value is not.
- **Tests:** `tests/test_exporters.py::test_docx_created` — its fixture is exactly the failing shape, `authors=["Smith A", "Jones B"]`, but it asserts only `len(doc.tables) >= 1` and `len(table.rows) >= 4`. `tests/test_readers_on_the_reader.py::test_the_docx_reports_declined_and_shows_no_value_for_withdrawn` builds `body = {r[0]: r for r in rows[1:]}` keyed on the label and takes `next(iter(body.values()))` — the label is used as a key and never asserted. No test reads the Study cell.
- **Existing row:** new
- **Proposed class / package:** 2 / P5 — the `IndexError` is a loud path failure; the wrong label is silent but is presentation of a correct row (lead may split: label → 3 / P7).

### L13-C3 — The DOCX table carries no paper identifier and does not say which arm, run or database it shows

The sibling xlsx has a "Field States" sheet with paper ids (per F09's trace), so the identifier exists in the package, just not in this artifact. A journal table omitting ids is a legitimate layout; the missing arm/run line is the part that is provenance.
- **Tests:** none asserts any identifying content of the DOCX.
- **Existing row:** extends F09 (the per-artifact half: this file is unlabelled even when the package is coherent)
- **Proposed class / package:** 3 / P5 — provenance of a delivered artifact; no stored value is wrong.

- **Evidence:**

### L13-C6 — The decision dropdown's validation is not enforced: error and prompt messages are set but never switched on

- **Pattern:** i
- **Evidence level:** reproduced (`L13_1_workbook_builder.py` `[a]`)

- **Tests:** `tests/test_adjudication.py` and `tests/test_ft_screening.py` assert sheet names and cell contents; grep for `data_validations` / `showErrorMessage` in `tests/`: no hit.
