# 12l-U07 — the write-boundary guard on blank values and non-value tokens (INT-i12-2, INT-i12-6); stored records counted as extracted (INT-l12-20)

P1 unit U07 under R612 and R607(c), with R619(c). Guard-side; not pin-affecting. No model call, no live write. Written from the tree at `b6f7fc1` (item 0, R619).

## I1–I3

- **I1 holds.** The two new codes, `BLANK_VALUE` and `NON_VALUE_TOKEN_AS_VALUE`, are constants of `engine/core/citation_guard.py` and appear nowhere else in `engine/` (grep). The Pass-1 feedback block renders `prompts._requirement(code, …)` for `rec.fatal`, which is drawn from `contracts.FATAL` — the Pass-1 contract vocabulary, a different set that this unit does not touch. The guard's offenders reach an `UncitedValueError`, a retry of the identical request, and at exhaustion a claim's `violation_codes`; none of these is a prompt. `pin_tuples.py` after the change is byte-identical to before.
- **I2, the sites** (all in `engine/agents/extractor.py::_extract_selected`, in the `except Exception` branch after `extract_paper_with_completeness`, unless stated):
  1. `stats["failed"] += 1`;
  2. `logger.exception("Paper %d extraction failed: %s%s", …)`;
  3. `progress.report(pid, "FAILED", …)`, which also feeds `progress.summary()`'s failed count;
  4. the closing line `"Extraction complete: %d extracted, … %d failed, %d total spans"`, from the same stats;
  5. `scripts/run_pipeline.py::_distribution_check`: `extracted_count=stats.get("extracted", 0), failed_count=stats.get("failed", 0)`, and the `distribution_check` telemetry row it writes from the summary.
  The run's close itself (`_finish_review_run` → `close_run`) records a status and a reason and no count. The retry driver's line "refused on all N attempts … is kept" describes the rule and was already right.
- **I3: the local path does not skip on a failed paper.** `run_pipeline._distribution_check` calls `run_post_extraction_check(…, strict=False, raise_on_collapse=False, skip_on_failures=False, min_population="arm")`. The skip rules, from `engine/validators/distribution_monitor.py`'s docstring: "`min_population=\"run\"` (default): skip when this run extracted fewer than 10 papers. `min_population=\"arm\"`: skip when fewer than 10 eligible papers hold a live claim for the arm, whatever this run did. `skip_on_failures=True` (default): skip when any paper in the run failed; False records `failed_count` without vetoing the check." So on the local path the one skip is an arm population under 10, and a failed paper is recorded, not a veto. The Class 1 the architect expected does not arise there. The cloud path (`CloudExtractorBase.run_distribution_check`) passes neither argument and takes both defaults: it skips under 10 papers extracted in the run or on any failure (F1).

## What changed

- **INT-i12-2** (`citation_guard.check_citations`): an empty or whitespace value that carries evidence — a non-empty snippet, or a validated citation count above zero — is an offender, `BLANK_VALUE`, in both modes. Without evidence it remains `VALUE_WITHOUT_CITATION`.
- **INT-i12-6, N13**: in legacy mode a value equal to the escape token or the contract-unmet token is an offender, `NON_VALUE_TOKEN_AS_VALUE`, with or without a snippet. `extractor.extract_paper` now passes the codebook's contract-unmet token to the legacy guard (`_contract_unmet_token`), at the enforce site and at the record-building site. Strict mode is unchanged.
- Each offender is refused before any write and retried under the bounded budget; at exhaustion its field is `contract_unmet` with the code, through the existing record builders. `engine/elicitation/pipeline.py` and `engine/core/extraction_events.py`, in the brief's list, needed no change.
- **INT-l12-20** (`_extract_selected`): `record_failure` returns what it wrote. When that is the exhausted attempt's record (stored as `extracted`), the paper is added to `stats["extracted"]`, its held fields to `total_spans`, the progress line reads `EXTRACTED`, and a warning says "stored as extracted after the retry budget" with the held, incomplete and `contract_unmet` counts. Only a paper failure reaches `stats["failed"]`, "extraction failed" and `FAILED`.

## R509 findings (none Class 1)

- **F1 — the cloud path's distribution check skips on any failed paper and under 10 papers extracted in the run (I3).** `CloudExtractorBase.run_distribution_check` takes `run_post_extraction_check`'s defaults, and raises on a collapse. The local path does neither. Unreachable while R71 keeps `enabled_arms` empty. Proposed Class 3, P7 (cloud), or a note on the cloud rows of P1.
- **F2 — `attempts` on a stored claim is the attempt its record was made at, not the attempts spent.** Since U06's attempt rule, three attempts refused the same way keep attempt 1's record, so the `contract_unmet` claim reads `attempts: 1` after a budget of three. R139's "with `violation_codes` and `attempts`" does not say which is meant. Seen while writing gate 1. Proposed: a note on A-11, or Class 3, P7.
- **F3 — `total_spans` counts different things on the two branches.** A stored exhausted record adds its held fields; a complete extraction adds `len(result.fields)`, tokens included. Proposed: no row.
- **F4 — `UncitedValueError` now also carries offenders that are not uncited values.** Its message lists the codes, so nothing is hidden; the class name and its first line ("a value with no evidence behind it") are narrower than what it carries. Proposed Class 3, P7.
