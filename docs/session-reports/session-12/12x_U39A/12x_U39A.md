## Q2 — test design

One form for every stage. The stand-in `_fake(**kw)` raises `_Sent(kw["messages"])`. `_Sent` is a
`BaseException`, so a call site's `except Exception` (the snippet retry's, preflight's) cannot swallow it, and
nothing after the call runs. Each runtime function is called with the render's own sentinel inputs.
`_assert_one` compares the role sequence, the message count, the canonical JSON and the lists. For the two
stages whose render concatenates variants (`elicitation_pass1`, `audit`), `_assert_variants` splits the render
at each `system` message. The number of runtime calls must equal the number of rendered chunks (the
variant count), each call must equal its chunk, and the concatenation must equal the render. Preflight
compares the runtime copy of the duplicated expression (`check_model`) with the render's copy. The
seed's stand-in returned a response and appended; this file raises instead. That form is needed for
`check_model`, whose `ollama.ps()` after the call would otherwise reach the Ollama fence.

Fixtures (I5): the live spec by `load_spec_for("surgical_autonomy")`, the elicited spec by
`model_copy` (the seed's form), the live codebook `data/surgical_autonomy/extraction_codebook.yaml`
(tracked), and pytest's `tmp_path`. **No fixture from `tests/` is used and none is needed.** The vision
test makes a one-page PDF with `fitz` in `tmp_path` and replaces `pdf_parser.base64` with a namespace whose
`b64encode` returns `SENTINEL_IMAGE` (finding 9). No stage needed an engine change or a new fixture.

## Q7 — findings

1. **The verifier test is defective, not the stage.** It reads `spec.screening_models.verifier`; the field
   is `verification` (review_spec.py:861 `add(self.screening_models.verification, "screening_models.verification")`;
   `tests/test_request_capture.py` passes `model=spec.screening_models.verification`). It fails on HEAD and
   under every mutation for that reason alone. It is left as written under Q3. The diagnostic shows the
   stage's lists equal on HEAD (`58fb9c2e…2452`) and different under m03 and m04.
2. **The first HEAD run was a harness error**: the `--basetemp` parent did not exist, every test errored in
   setup, and no body ran. It was re-run with the directory created, and both outputs are kept.
3. **Audit's variant set is decided in two places, measured.** The runtime passes the codebook's `type`
   (audit_events.py:166 `types = {f["name"]: f.get("type", "text") for f in codebook.fields}`, :234
   `field_type=types.get(c.field_name, "text")`). On the live codebook those types are `categorical` 11,
   `free_text` 8 and `numeric` 1. The builder writes the value into the prompt (auditor.py `Field type:
   {field_type}`), and its branch is `if field_type == "categorical"`, otherwise the text question. The render's two
   variants are `"text"` and `"categorical"`. So for 9 of 20 fields the runtime sends a `Field type:
   free_text` / `numeric` line that no rendered variant carries. `"text"` is reached only by the default.
   The test uses the render's inputs and passes, so it cannot see this; the gap is between the caller's
   vocabulary and the render's sentinel.
4. **`pdf_quality` is rendered by `render_messages` but never hashed at runtime.** No `open_run` declares
   it: `prompt_hash` has two callers, both in `resolve_run`, and `pdf_quality_check.py:178` resolves
   `stage_config("pdf_quality", …)` outside any manifest. Q0 lists it as a hashed stage. No test was built.
5. **Q0's `vision_parse` "no (parse precedes the run)"** against `run_pipeline.py:490` `"parse":
   ("vision_parse",)`: a run started at `parse` declares it. It is on the local run path and was built. Q0's
   `extract_pass2` "(both arms)" is two render branches, built as two tests.
6. **Pins carry the extraction arm's stages only.** `pin_tuple` keeps `for key, r in
   sorted(resolved.items()) if r.arm_name == arm_name`. So for audit, preflight, the two screens and vision,
   a change on both sides moves the manifest's `prompt_hash` but no pin (m20, m21, m23, m25: both pins
   unchanged). R707(b)'s "a change that lands green has changed both sides and moved the pin" holds for the
   four extraction stages (m10, m12, m13, m15, m17, m18) and not for the others. This is a reading.
7. **Compositions above the call site are not exercised**, which is the seed's scope too. The tests drive
   each call site with the render's inputs, so they do not cover `elicit`'s loop (attempt 2 only when
   `first.failed_fields`, its feedback `build_feedback_block(first, codebook)`), `extract_paper_elicited`'s
   `pass2_priming` over the evidenced records, or `audit_events`' choice of `field_type` (finding 3). For
   the elicited Pass 2, the runtime input is the hash-side `sentinel_priming_message`, which shares
   `pass2_priming` with the runtime. Every M1 here is at the `ollama_chat` call.
8. **No existing test compares messages with the render** (Q5). `test_request_capture` removes
   `messages` before its comparisons.
9. **The vision test's harness** makes a one-page PDF in `tmp_path` and replaces `pdf_parser.base64`
   for the test's duration. No fixture is added under `tests/`.
10. **The fence outside `tests/`** comes from `-p conftest` with `PYTHONPATH=.:tests`, asserted by
    `test_the_suite_fences_are_active`. Under `tests/` the conftest applies by location.
