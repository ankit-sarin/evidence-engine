**Expectation check.** The brief expected whitespace normalisation to give most of the marginal gain and
de-hyphenation, ligature folding and soft-hyphen removal each to give little. Both held, more sharply than
stated: the three give nothing at all on this corpus.

**What the corpus's text-pathology rate is.** 4.8% of model-typed snippets miss the raw text for a reason the
text carries, and that reason is whitespace. The other half of the snippets are not in the text under any of
the six forms; that is the model not quoting verbatim, which no text transform addresses.

## Method

Script and outputs: `docs/session-reports/session-12/12h_rd/rd2_substring.py` → `rd2_substring.json`, and
`rd2_spans.csv` (one row per span, 3,760 rows, with the first stage at which it matched). Run time 4 s.

**Population.** `evidence_spans` joined to `extractions` on live: 3,760 spans, 190 papers, one extraction per
paper, every one by `deepseek-r1:32b`, extracted 2026-03-15 to 2026-03-18. The source text of a span is the file
its paper's `parsed_text_refs` row names.

**The six texts**, applied cumulatively and in R563's order, to the snippet and to the source text alike. A span
matches at a stage when the transformed snippet is non-empty and is an exact, case-sensitive substring of the
transformed text.

| stage | definition |
|---|---|
| raw | nothing applied |
| whitespace-normalised | every run of whitespace becomes one space; ends stripped |
| comment-stripped | the engine's own `COMMENT_RE` (`engine/elicitation/units.py`, `<!--.*?-->`, imported) becomes one space |
| de-hyphenated | a hyphen (ASCII `-` or U+2010) between two word characters and followed by whitespace is removed with that whitespace: `auto- matic` → `automatic` |
| ligature-folded | U+FB00 to U+FB06 become `ff` `fi` `fl` `ffi` `ffl` `ft` `st` |
| soft-hyphen-removed | U+00AD removed; where it sat between word characters before whitespace, the whitespace goes with it |

No match was lost by a later stage (0 non-monotone cases).

## PROPOSED class and package (RB-2: locator-2, A-9, A-10)

CC proposes; the PI rules. R534 stands unamended and is quoted, not modified: "A-10: a versioned locator-2 with
comment-aware normalisation, decided together with A-9 from 12g's measurements; audit-side, outside the pin.
INT-g6-1: units become exact slices of the source text; this changes the elicited request and lands before the
freeze (R539). A materialisation-time EXACT check is the minimum loud fix for both."

What this read adds to that decision, and what it cannot:

- **A-9 (hyphenation, soft-hyphen, ligature misses).** Measured on the corpus now, not only on 12g's sample:
  0 spans recovered by any of the three across 3,562 legacy snippets; no parsed text contains a soft hyphen;
  locator-1's NFKC already folds ligatures. **PROPOSED: Class 3, package P7, as a recorded measurement with no
  code change before the tag** — it takes a class at last (the row has had none), and it leaves P1. Reopening
  condition: a review whose parsed texts carry soft hyphens or line-break hyphenation (a check a parse-quality
  gate could make).
- **A-10 (materialised quotes built from comment-stripped text, located against raw text).** This read does
  **not** bound A-10. Its one-span comment gain says model-typed snippets rarely straddle a comment; a
  materialised quote straddles one whenever cited units do, which is a property of the unit builder, not of the
  text. A-10's own measurements stand: 12f's "first 60 parsed files: 110 single units, 1,665 adjacent pairs,
  4.5%" and 12g's 0 of 177 on Rehearsal A. **PROPOSED: A-10 stays Class 1, P1**, closed by the two things R534
  already names — INT-g6-1 (units as exact source slices) and the materialisation-time EXACT check — because
  once a unit is an exact slice of the source, a quote built from units cannot differ from the source by a
  comment.
- **locator-2.** On legacy spans its three candidate normalisations recover 1 span of 3,562 beyond locator-1's
  exact stage. **PROPOSED: locator-2 is not built before the tag.** It is audit-side and outside the pin (R534),
  so deferring it changes nothing Run 7 sends, and a new locator version can be run over stored claims later,
  since every `citation_located` event records the version that decided it.

None of the three proposals is pin-affecting (R539): the locator is audit-side. INT-g6-1 is pin-affecting and is
already in P1 for that reason; nothing here moves it.

Options for the PI, in one line each: (a) as proposed — A-9 to Class 3 / P7 as measured, A-10 closed by
INT-g6-1 and the EXACT check, no locator-2 pre-tag; (b) build locator-2 pre-tag with comment-aware
normalisation only (for A-10, belt and braces alongside INT-g6-1); (c) build locator-2 pre-tag with all three
normalisations as R534's first clause reads. This read supports (a) over (c) on A-9's evidence and cannot choose
between (a) and (b), which turns on whether INT-g6-1 lands as specified.

## Confidence

High for the counts: one deterministic script over every span, 4 s, each transform defined above and applied to

and another review's PDFs may parse differently.
