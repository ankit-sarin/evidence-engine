# 12l-U08 — value divergence recorded where a reader sees it (INT-i12-3, N11); what `attempts` means on what is stored (R620(c))

P1 unit U08 under R612(j) (D9, Option A), R620(c) and R607(c). Storage-side; not pin-affecting. No model call, no live write. Written from the tree at `ed112d1` (item 0, R620).

## I1, I2

- **I1 holds.** The Pass-1 value is `p1.records[name].value` (`contracts.FieldRecord.value`, already stripped) in `engine/elicitation/pipeline.py::extract_paper_elicited`. The loop that builds one span per field reads it (`rec = p1.records[name]`) and runs **before** `enforce_terminal_states` / `enforce_completeness` / `enforce_citations`. So the same values are in scope at both sites that build the stored record: the refusal site (`except (IncompleteExtractionError, UncitedValueError) as exc: exc.record = _record(…)`) and the write site (`write_extraction_events(db._conn, _record(…))`). They are now collected in `pass1_values` and passed by `_record` on both. The legacy path has no Pass-1 value: its Pass 1 is a reasoning trace.
- **I2 holds: one reader, and it reads the same way.** `engine/core/effective.py::_classify_claim`, row 15: `EffectiveValue(None, CONTRACT_UNMET, 15, {"violation_codes": ev.payload.get("violation_codes"), "attempts": ev.payload.get("attempts")})`. It copies the key into the provenance and decides nothing on it. Nothing in `engine/`, `scripts/` or `analysis/` reads that provenance key or the payload key otherwise (grep; `analysis/eval/analyze_capture01.py` reads its own JSONL rows' `attempts`, not a claim's). The two writers are in `extraction_events.py`.

## What changed

- **`engine/core/events.py`** declares three payload keys: `PAYLOAD_PASS1_VALUE = "pass1_value"`, `PAYLOAD_ATTEMPTS = "attempts"`, `PAYLOAD_KEPT_ATTEMPT = "kept_attempt"`.
- **Divergence** (`extraction_events.py`): `diverges(pass1_value, stored_value)` is the existing comparison, exact after strip; `FieldOutcome.pass1_value` is set by `elicited_record(pass1_values=…)` only for a value that differs; `plan_extraction_events` writes it on the asserted claim. `divergence_kind` classes a pair as `case_or_whitespace` when it is equal under casefold and whitespace collapse, else `substantive`.
- **The run summary**: `run_extraction_summary` adds `value_divergence` — `{"substantive": {"count", "fields"}, "case_or_whitespace": {"count", "fields"}}`, counted over the run's asserted claims, `fields` being field → number of claims — and `_extract_selected` logs it when either count is non-zero.
- **`pipeline.py`**: collects `pass1_values`; the two readerless writes (`_LAST_PASS2_TELEMETRY["value_divergence"]`, `["n_value_divergence"]`) are removed; the module docstring states where divergence is recorded.
- **R620(c)**: `ExtractionRecord.attempts` stays the attempt the record was made at; `attempts_spent` is set by the retry driver at exhaustion (`dataclasses.replace(kept.record, attempts_spent=max_attempts)`), and `ExtractionRecord.spent` is what is stored as `attempts`. `attempts` and `kept_attempt` are written on a `contract_unmet` claim, on the `extracted` paper event, and in a floor failure's detail.
