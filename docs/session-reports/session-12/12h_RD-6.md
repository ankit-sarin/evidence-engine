## Answer

**Long-standing design.** Determined from git; the March records are consistent with it and could not have
determined it alone.

1. **The two passes never differed.** In every one of the 15 commits that touched `engine/agents/screener.py`,
   from the first (`b50ffba`, 2026-02-23) to HEAD, `screen_paper` accepts `pass_number` and never reads it. The
   two calls in the loop have always carried the same arguments apart from that number: same model, same role,
   same prompt, temperature 0, no seed.
2. **Session 7 collapsed nothing.** The MANIFEST-01 commit `1cd80a4` moved the literals `options={"temperature":
   0}`, `think=False` and the format schema into the resolver. Before it and after it, pass 1 and pass 2 send
   the same request as each other.
3. **Generated text does claim a dual-pass.** The methods section says "a dual-pass local LLM approach". One
   architecture document goes further and describes a difference between the passes that the code has never
   had. PRISMA output does not mention passes.

**Expectation check.** Both expectations held: both passes at temperature 0 since at least session 7 (in fact
since the first commit), and the March rows cannot show temperature, seed or prompt. The brief's acceptable
partial answer, "undetermined from the March records; determined from git", is the shape of this answer.

**Reading, as CC's judgement.** Same model on both passes is a recorded fact. A 99.84% agreement rate with
about two thirds of rationales word-for-word identical is what two identical requests at temperature 0 produce
when the runtime is not bit-reproducible; it is not what two differently-prompted or differently-seeded passes
would be expected to produce. That is consistency, not proof: the rows cannot exclude a difference that happened
to change almost nothing. Git is what excludes it. One caveat on the rows themselves: the expanded-search
decisions reached this table through migration 003's backfill, so `decided_at` on those rows is what the
backfill wrote.

## Answer in the ruling's categories

**Long-standing design**, not a regression.

- *Did the two passes ever differ (temperature, seed, prompt, model)?* No, at any commit.
- *Did session-7 configuration work collapse a designed difference?* No. There was none to collapse, and the
  session-7 diff changes where the values come from, not the values.
- *Does any generated text claim a dual-pass check?* Yes: the methods section; and the architecture documents,
  one of which describes a difference between the passes that never existed in code.

What the design is, stated plainly: the primary screen sends the same request twice. Its second pass can
disagree with its first only through runtime nondeterminism. On live that happened 17 times in 10,687. The
independent check in abstract screening is the cross-family verifier, not the second pass.

## PROPOSED class and package

CC proposes; the PI rules. Two parts, because the finding has two.

**(1) The wording — PROPOSED: fold into B-F07 / E-METHODS / C36 (Class 1, package P3), no new row; the
architecture document's false line to P7.** Under the plan's rule "Stated guarantees are checked against behaviour —
docstrings, generated methods text, and "refuses any …" claims", a methods sentence that says "dual-pass" reads as a second look and is,
in mechanism, a repeat. B-F07's stated fix ("Render a visible placeholder for any sentence the run's recorded
calls do not support") is the same pass over the same generator. The methods sentence should say what was done:
each abstract was screened twice with an identical request, and a disagreement flags the record.

**(2) The mechanism — PROPOSED: INT-g12-5 moves from Class 1 (conservative) to Class 3, package P7, as a
recorded design fact; any change to the mechanism is a post-tag design decision, not a pre-tag fix.** It makes no
stored result, provenance or human gate wrong: every decision row is true to a call that was made, and the
verifier and the adjudication gate stand behind it. It costs one redundant `qwen3:8b` call per abstract.

Options for the mechanism, with their relation to the pin (R539 concerns what the elicited extraction run sends;
abstract screening names no arm, so none of these is pin-affecting):
- (a) **Keep, and describe truthfully** (part 1). No behaviour change; screening decisions stay comparable with
  March's.
- (b) **Make pass 2 differ by design** — a declared seed per pass, or the strict criteria on pass 2 as
  `pipeline.md` describes. This changes what screening sends and so what it decides; it belongs with S4
  (evidence-backed exclusion, verified across families) and would need its own measurement.
- (c) **Drop pass 2.** Halves primary-screen calls; removes the 17-in-10,687 nondeterminism flag; changes the
  shape of `abstract_screening_decisions` going forward and the adjudication exporters that read both passes.

CC's PROPOSED choice: **(a) before the tag; (b) or (c) decided at S4**, where the screening design is reopened
anyway.

## Confidence

High that this is long-standing design: the AST read covers every commit of the file, and the call-line census

March (an Ollama Modelfile parameter, an environment variable). Neither would distinguish pass 1 from pass 2,
since both passes named the same model in the same process seconds apart.
