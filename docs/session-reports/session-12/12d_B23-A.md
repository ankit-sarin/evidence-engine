## Q4. What a verdict can and cannot detect, for an unlocated claim — READ (reasoned from Q1's template)

The verifier is asked whether the value follows from the snippet. It is told the snippet is "from
paper" and has no means to test that.

| case | detectable? | why |
|---|---|---|
| A fabricated snippet that supports the value | **No.** | The template presents the snippet as "Source snippet from paper". A self-consistent invention reads as `verified`. This is the case the locator just failed on, so it is the case every call is made for. |
| A real passage paraphrased, supporting the value | Reads as `verified`. | Correct outcome, but indistinguishable from the fabricated case: the model sees the same thing in both. |
| A real passage paraphrased with the meaning changed | **No**, if the paraphrase supports the value. | The original wording is not shown. |
| A snippet that supports the value but is from another paper or arm | **No.** | Nothing in the request identifies the paper. |
| A snippet that does not support the value | **Yes.** | This is the question asked. |
| A value that misreads a genuine snippet (wrong number, wrong category) | **Yes**, to the model's ability. | Same. |

So for an unlocated claim the verdict measures the internal consistency of the extractor's own
(value, snippet) pair. It cannot separate "paraphrase of real text" from "text that is not in the
paper", which is the distinction `located = false` leaves open.

One more property of the request: the template instructs the model to emit `"grep_found": true`
literally, and `AuditVerdict.grep_found` is required. `audit_run` stores `v.status` and
`v.reasoning` only. See F2.

## Classification

B23 as stated is **(i) or (ii), depending on the design; never (iii)**:

- **(i)** if the outcome is to make the code and the documents say what the call does (remove or
  keep the unused parameter, correct "source text" wording in docstrings and architecture docs). No
  request changes.
- **(ii)** if the request changes: text is sent, or the call is retired. The brief defines (ii) as
  "both pins move"; that part does not hold (Q6). The audit stage's `prompt_hash` moves, the request
  capture and prompt-hash coverage tests move, and the arm pins do not.
- **(iii)** is not reached by any candidate below. `audit_verdicts` already has the columns a
  verdict needs; a design that recorded which text or window the verifier saw would add a column,
  and would then be (iii).

## Findings beyond the questions

- **F1 — the audit stage is outside the arm pin** (READ and MEASURED; Q6). A changed audit prompt,
  model or options does not refuse a later run of the same arm; it is visible only as a different
  `run_stage_configs` row. Whether verdicts under different audit configurations should be
  comparable within an arm is not established by this read. Candidate row; not chased.
- **F2 — the template tells the model to answer `"grep_found": true`, and the field is required and
  discarded** (READ; Q1, Q4). `AuditVerdict.grep_found: bool` is in the `format` schema; the
  instruction hard-codes `true`; `audit_run` stores status and reasoning only. Any change is a
  request change. Candidate row; not chased.
- **F3 — a non-`ValidationError` exception from the audit call leaves `audit_run`** (READ; Q7). The
  `try` around `semantic_verify` catches `ValidationError` only. Unreachable for input-fit with
  today's roughly 200-token request; reachable under design A for paper 415. Noted for A and B.
- **F4 — the verdict has no reader** (READ; Q5). `audit_verdicts` and the report's
  `verified`/`flagged` counts are written, logged and never read by code in `engine/`, `scripts/`
  or `analysis/`. Consistent with the plan's "telemetry, never a filter"; stated because it bears on
  design E.
- **F5 — architecture docs describe the retired auditor** (READ; Q3). `docs/architecture/pipeline.md`,
  `state-machine.md` and `modules.md` still describe `DEFAULT_AUDITOR_MODEL`, `SEMANTIC_ONLY_TIERS`,

- **F6 — `scripts/smoke_test_fixes.py` is `audit_span`'s only non-test caller** (grep). It is already
