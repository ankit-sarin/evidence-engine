## 1. The locator (2(a))

**Module and entry.** `engine/core/locator.py`, public entry `locate`:

```python
def locate(parsed_text: str, snippet: str | None, *,
           threshold: float = FUZZY_THRESHOLD) -> LocateResult:
```

**Constants.** `LOCATOR_VERSION = "locator-1"` and `FUZZY_THRESHOLD = 0.85`, both module-level in
`engine/core/locator.py` (I2 holds). The module docstring: "`LOCATOR_VERSION` names this algorithm.
Changing the normalisation, the window rule or the threshold is a new version, never an edit, because
every `citation_located` event records the version it was decided by."

**The algorithm, quoted.**

```python
    norm_snippet = normalize(snippet) if snippet else ""
    supplied = bool(norm_snippet)
    bridged = bool(supplied and INVALID_SNIPPET_RE.search(snippet))
    ...
    norm_text = normalize(parsed_text)
    if norm_snippet in norm_text:
        return LocateResult(True, EXACT, 1.0, True, bridged)
    snippet_words = norm_snippet.split()
    text_words = norm_text.split()
    size = len(snippet_words)
    ...
    for i in range(max(1, len(text_words) - size + 1)):
        window = " ".join(text_words[i: i + size])
        ratio = SequenceMatcher(None, norm_snippet, window).ratio()
        if ratio > best:
            best = ratio
    located = best > threshold
```

- `SequenceMatcher(None, norm_snippet, window)`: `isjunk=None`, **no `autojunk` argument** (so the
  default, `True`), `.ratio()` (not `quick_ratio`). The sequences are **strings, compared character by
  character**: `a` is the normalized snippet, `b` the window.
- Threshold: `FUZZY_THRESHOLD = 0.85`, strict (`best > threshold`).
- Candidate windows: every run of `size` consecutive words of the normalized text, where `size` is the
  snippet's word count; the whole text is scanned and the best ratio kept as `score`.
- `normalize`: smart quotes and dashes straightened, NFKC, `(?<=\w)\.(?=\w)` → space, lowercase,
  whitespace collapsed.
- Outcomes: `EXACT` (normalized substring, score 1.0), `FUZZY` (best window ratio > 0.85), `NONE`.
  `LocateResult(located, kind, score, snippet_supplied, bridged)`, a frozen dataclass.
- Text read: whatever the caller passes. The one production caller passes `read_parsed_text(ref)`,
  "The verified text, decoded exactly as `Path.read_text()` decoded it" — the **raw** parsed text, not
  a comment-stripped form (the same text units-2 slices, R-4).

## 4. The fuzzy fixtures and the autojunk heuristic (2(d))

The heuristic, from the installed `/usr/lib/python3.12/difflib.py` (Python 3.12.3; the HTML
documentation is not installed on this box, so the source and docstring are quoted instead):

```python
        Optional arg autojunk should be set to False to disable the
        "automatic junk heuristic" that treats popular elements as junk
        (see module documentation for more information).
```

```python
        # Purge popular elements that are not junk
        self.bpopular = popular = set()
        n = len(b)
        if self.autojunk and n >= 200:
            ntest = n // 100 + 1
            for elt, idxs in b2j.items():
                if len(idxs) > ntest:
                    popular.add(elt)
```

It applies to `b` only — in `locate`, the **window** string — when it is 200 characters or longer, and
drops every character occurring more than `n // 100 + 1` times. In a 380-character English window
that is almost every letter and the space.

## 9. Findings

- **F1.** `locate` constructs `SequenceMatcher(None, norm_snippet, window)` with no `autojunk` argument,
  over characters, and the window (`b`) is the snippet's word length of normalized text, so every
  snippet of 200 or more characters is scored under the heuristic (`if self.autojunk and n >= 200`).
- **F2.** On a 382-character, 70-word passage, 3 changed words score 0.9752 under autojunk against 0.9856
  without. Across 300 seeded 3-word edits, autojunk gives min 0.8136 and 6 not located; without it the
  minimum is 0.9883 and 0 are not located. The row's "0.732 against 0.974" is not reproduced on this
  passage; its direction and mechanism are.
- **F3.** No existing fuzzy fixture is 200 characters or longer (longest 70), so no test can see the
  heuristic, and all 10 fixtures keep their outcome and score under `autojunk=False`.
- **F4.** `analysis/provenance/classifier.py` states why it passes `autojunk=False` ("autojunk MUST stay
  off …"); `engine/parsers/font_audit.py` passes it with no comment saying why.
- **F5.** `locate` has one production caller, `audit_events.audit_run`. `auditor.grep_verify` and
  `auditor.audit_span` also call it and have no production caller.
- **F6.** `LOCATOR_VERSION` (`"locator-1"`) is written into every `citation_located` payload, the
  `audited` paper payload and the located event's `actor_name`. It is read by no engine, script or
  analysis code, and pinned by one test (`assert p["locator_version"] == L.LOCATOR_VERSION == "locator-1"`).
- **F7.** `audit_run` skips any claim that already has a `citation_located` event whatever its version,
  so a version bump re-locates nothing already located (live has 0 field events; the retained
  throwaways keep `locator-1`).
- **F8.** A verbatim quote of a passage containing `…` or `...` is `located True, kind exact, score
  1.0, bridged True`. `bridged` is read by nothing outside the locator and its tests, and `audit_span`
  returns `invalid_snippet` for it before locating.
- **F9.** `INVALID_SNIPPET_RE` has exactly three callers: `locate` (on the pipeline through
  `audit_run`), `extractor._has_invalid_snippet` (on the pipeline only when `elicitation` is false; the
  live spec reads `elicitation: false`), and `auditor.audit_span` (no production caller).
- **F10.** On the elicited path every stored snippet is an exact raw-text slice (U01, R-4). `locate`
  therefore returns EXACT for those claims before the window loop, and INT-i12-7 affects only claims
  whose snippet is model-typed (the non-elicited path).
- **F11.** Scoring every window of a 156,196-character text against a 383-character snippet takes a
  median 5.214 s with autojunk on and 43.011 s with `autojunk=False` (×8.2).
- **F12.** Neither row changes a pin input: the pin tuple holds the arm's stages, the codebook hash, the
  client library and segmentation, and names no locator constant or the regex.

## 10. Options — PROPOSED

**INT-i12-7.**
- **(A) `autojunk=False` at the locator's one `SequenceMatcher` call**, under a new `LOCATOR_VERSION`.
  - Changes: the score of every fuzzy candidate of 200 or more characters.
  - Fixes: the heuristic's under-scoring (§6.1: worst 0.8136 → 0.9883; 6/300 → 0/300 not located).
  - Risks: (i) it can raise long scores past 0.85 that were below it, so some claims that are not
    located today become located — the change cuts both ways and is not limited to recoveries;
    (ii) cost: up to ×8.2 per non-exact long claim on the largest auditable text (F11). On an elicited
    Run 7 this is confined to non-exact claims, which F10 says are few.
  - Pin effect: none.
- **(B) A threshold change instead.** This would be wrong. The defect is that the ratio depends on
  string length through a heuristic: two claims with the same edit score differently by length, and
  differently by where the edit falls (§6.1 sweep). A lower threshold would admit worse short-snippet
  matches to rescue long ones, and would still leave the long-snippet score as an artefact. Below 200
  characters the score is already correct (§6.1, §4). Pin effect: none, but it is a different, wider
  change.

**INT-i12-8.**
- **(A) `bridged` is true only when the snippet's ellipsis is absent from the located span.** For an
  EXACT match, `bridged = regex fires on the snippet and the normalized snippet's ellipsis is not in the
  matched text`, which, since the match is a substring, comes to "never bridged when EXACT". For FUZZY,
  the same test against the best window.
  - Changes: `bridged` in new `citation_located` payloads.
  - Fixes: F8's false `bridged=True`.
  - Risks: none to `located`; the regex stays as the trigger.
  - Pin effect: none.
- **(B) The regex check moves after `locate` and applies to the span difference** (an ellipsis is
  bridging when it stands in the snippet where the located text has none).
  - Same effect as (A) on `bridged`; it also gives `audit_span`'s precheck a located basis.
  - Risk: `audit_span` has no production caller, so the auditor half fixes no pipeline behaviour (§3).
  - Pin effect: none.
