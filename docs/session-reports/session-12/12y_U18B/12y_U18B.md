## §4 The manifest host, and the limits of this commit

- `ollama_host` is a key of the manifest body JSON, beside `host` (the machine's name), and is covered by
  `manifest_sha256` (`sha256_canonical(manifest)`). That is proven by
  `test_u18_the_manifest_records_the_ollama_host`.
- `host` is also a `run_manifests` column (`020_run_manifest.py:152`, `022_…:280`, `host TEXT NOT NULL`).
  **An `ollama_host` column is owed to migration 023 (P6)** and is not built here (R722(f)).
- **The resolver and the live client** (R724(c)). The import-time host (`ollama_host()`) is what the
  refusal checks, what the manifest records, and what the restart poll names. The digest read, the
  preflight's ps and the chat calls go through the live `_client`, so they follow it if it is rebound.
  `server_context_length` reads the live client's host through `is_local_service_host`. In production the
  two are the same object built from the same value.
- **The R722(c) limit:** a `_client` rebound in-process after import is not a supported path and is not
  refused. `analysis/eval/run_qualgap01.py:91` (`oc._client = ollama.Client(host=host, …)`) is the one
  site that does it. `test_u18_a_rebound_client_at_a_fake_host_is_not_refused_at_open_run` pins the limit
  on purpose: the digest is then read through that same fake, never from a third object (A-4b's
  acceptance test).
- **The review-session limit** (R724(d)): `open_review_session` → `open_run`, so a human review session is
  refused under a non-loopback `OLLAMA_HOST` too, although it sends nothing to Ollama. As ruled, the
  refusal applies to every run kind.

  adds that.

  digest; that change is commit 2's.
- **Owed to 023 (P6):** the `run_manifests.ollama_host` column (R722(f)).
