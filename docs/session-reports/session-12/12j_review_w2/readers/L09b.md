### L09b-C1 — the abstract page drops the pass-2 decision: a paper flagged because pass 1 and pass 2 disagreed is shown with pass 1 only
- **File / function:** `abstract_adjudication_html.py`, `_query_abstract_flagged`
- **Pattern:** v (reader drops data), i (docstring: "with dual-model screening rationale")
- **Evidence level:** reproduced
- **Evidence:** the query fetches both passes, the loop keeps one:
  `"SELECT pass_number, decision, rationale, model FROM abstract_screening_decisions WHERE paper_id = ? ORDER BY pass_number"` then
  `for r in rows:` / `if r["pass_number"] == 1:` / `primary_decision = r["decision"]` / `primary_rationale = r["rationale"] or ""` — there is no `else`, no pass-2 key in the result dict, and the card has one "Primary" panel.
  The flagging rule (`engine/agents/screener.py`, `run_screening`): `if d1.decision == "include" and d2.decision == "include": … elif d1.decision == "exclude" and d2.decision == "exclude": … else: db.update_status(pid, "ABSTRACT_SCREEN_FLAGGED")`.
  Reproducer output: `pass-1 rationale on card : True` · `pass-2 rationale on card : False` · `word 'exclude' on card   : False`.
- **What goes wrong:** for every paper flagged by primary disagreement (the only flag route on `run_pipeline`'s live path — `run_verification` has no production caller, E9), the reviewer sees "Primary: include, <rationale>" and "Verifier: — / Decision: —". The dissenting decision and its rationale — the reason the paper is in the queue — are in the database and not on the page. When pass 1 was the exclude, the reviewer sees an exclude with nothing against it. A parse-error flag where pass 2 was malformed looks identical (pass-1 row committed, F13(a)).
- **Refutation tried:** looked for a second panel or a JS use of pass 2 (none; the page embeds no data object); checked whether pass 1 and pass 2 are distinguishable at all — RD-6 says they are the same request sent twice, which makes the disagreement the only information the pair carries, and it is the part dropped. `screening_adjudicator._collect_db_flagged` has the same `ORDER BY pass_number` query (outside this lot, not read to the end).
- **Tests:** none for this module. A test that should exist: a paper with include/exclude rows, assert both rationales on the card.
- **Existing row:** new. (F13 names this loop only for the tie between two pass-1 rows; A13 for the verifier `ORDER BY id DESC`.)
- **Proposed class / package:** 1 / P4 — a human gate decides without the engine's dissenting record.

### L09b-C2 — the decisions file the pages emit carries a bare `papers.id` and nothing else: no title, DOI, review, generation time or queue identity for an importer to check

- **Pattern:** vi (iv for the missing review/generation identity)
- **Evidence level:** code order (record shape confirmed by the reproducer)
- **Evidence:** abstract: `output.push({ paper_id: pid, decision: dec === "INCLUDE" ? "ABSTRACT_SCREENED_IN" : "ABSTRACT_SCREENED_OUT", note: … })`; FT: the same with `"FT_ELIGIBLE" : "FT_SCREENED_OUT"`. `const blob = new Blob([JSON.stringify(output, null, 2)], …)` — the file is the bare array. The review appears only in the download's name: `a.download = REVIEW + "_abstract_adjudication_decisions" + (isFinal ? "" : "_draft") + ".json"`. `generated` is printed in the subtitle and not exported. A draft and a final differ in file name only.

Both fill the title **from the database by the key**, so the stored adjudication row's title is the database's, never the reviewer's.
