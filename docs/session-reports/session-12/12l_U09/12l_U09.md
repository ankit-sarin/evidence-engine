## I1, I2

- **I1 holds.** `engine/elicitation/terminal.py::accept_attempt`:

  ```python
  if second is None:
      return first, 1
  n1 = n_contract_unmet(terminal_states(first, codebook), codebook)
  n2 = n_contract_unmet(terminal_states(second, codebook), codebook)
  ```

  It decides per result, never per field: one whole attempt or the other, on the count of `CONTRACT_UNMET` fields. An unparseable attempt 2 parses to no entries, so `check_response` gives every expected field `FIELD_MISSING`; `n2` is then the number of expected fields, which is never below `n1`, and attempt 1 is kept (attempt 1 too on the tie where it failed every field).
- **I2, attempt 1's duplicate path as it stands (unchanged).** `check_response` raises `DuplicateFieldError`; `run_pass1` attaches the call's hash and re-raises; `elicit` has no earlier result, so it propagates; `extract_paper_elicited`'s handler sets `exc.arm`, builds `exc.record = _record({}, duplicated=exc.duplicated, presented_context_sha256=ctx_hash, context_chain=(ctx_hash,))` and re-raises. `DuplicateFieldError` is a subclass of `IncompleteExtractionError`, so the outer driver retries it under the one budget. At exhaustion the record holds the duplicated field as `contract_unmet` (`DUPLICATE_FIELD`) and nothing else, so it is under U06's floor and the paper is `extraction_failed` / `held_fields_below_floor`, with a one-hash context chain. ## What changed

All in `engine/elicitation/pipeline.py`:

- **`run_pass1`** builds the call's telemetry before checking the response, and on `DuplicateFieldError` attaches it to the exception as `exc.telemetry`: the prompt and content sizes, the raw response, the request hash, `parse_path: "duplicate_field"`, an empty per-field summary and `duplicated_fields`. It still attaches `request_hash` and re-raises, so attempt 1's path is as before.
- **`elicit`** catches `DuplicateFieldError` on attempt 2 only: it appends that telemetry entry, logs a warning naming the fields, and returns attempt 1's result as accepted (attempt number 1). The duplicate response is never parsed into a result, so nothing of it can be merged and no duplicate is collapsed.
- **`extract_paper_elicited`** needed no change for the chain: `pass1_hashes` is taken from every returned telemetry entry, so attempt 2's hash follows attempt 1's. Each `attempts` entry of the telemetry row gains `duplicated_fields` (empty except for such an attempt).

## R509 findings (none Class 1)

- **F1 — a duplicate on Pass-1 attempt 1 leaves no raw response in telemetry.** The outer driver's retry rows take `extra` from `_LAST_PASS1_TELEMETRY["elicitation"]`, which is cleared at the start of each attempt and never set when Pass 1 raises. `exc.telemetry` now carries that call's entry, and the driver (`extractor.py`, not in this unit) does not read it. Attempt 1's path is out of scope here. Proposed Class 3, P7, or with the row that owns attempt 1's duplicate path.
- **F2 — `DuplicateFieldError`'s docstring says "the rest of the paper stores", and on the elicited Pass-1 path nothing else exists to store.** The record is built from `{}`, so since U06's floor a paper whose Pass 1 names a field twice on attempt 1, three times running, fails under the floor rather than storing 19 fields. The docstring is in `completeness.py`. Proposed: a note on INT-i12-5 for a ruling on attempt 1's path.
- **F3 — the refusal's log line names an empty arm.** `check_response` raises `DuplicateFieldError(arm="")` and the message is built then; the handler sets `exc.arm` afterwards, so the driver logs "Paper 7 (): incomplete extraction". `contracts.py` is read-only here. Proposed Class 3, P7.
- **F4 — `duplicate_field` is a new `parse_path` value in telemetry.** `parse_container`'s own values are `direct`, `recovered_braces`, `recovered_marker_tokens` and `unparseable`; this one marks an attempt refused after its container parsed. It exists only in the telemetry entry: no `Pass1Result` carries it, so `Pass1Result.ok`, the one place that tests a `parse_path`, never sees it. Proposed: no row.
