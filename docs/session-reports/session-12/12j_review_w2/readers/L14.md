### L14-C1 — a cell with no value is scored as the rater answering "absent"
- **File / function:** `engine/analysis/concordance.py::load_arm` + `align_arms`;
  `engine/analysis/scoring.py::_verdict`; `engine/analysis/metrics.py::_hashable`
- **Pattern:** ii (and i — the contract `test_site5_terminal_states_are_dropped_from_the_arm` states)
- **Evidence level:** reproduced
- **Evidence:** `load_arm`: `if ev.value is None: continue` — docstring: "`missing`, `declined`,
  `contract unmet`, `withdrawn` and `out of scope` leave the key absent". `align_arms` then gives
  that side `fields_b.get(fname)` = `None`. `_verdict`:
  `if norm_a is None and norm_b is None: return "MATCH", "both absent"` /
  `if norm_a is None or norm_b is None: ... return "MISMATCH", f"one absent, one '{present}'"`.
  `_hashable`: `if label is None: return ABSENT_LABEL` ("Absence is a rater's answer").
  Repro C1: `A='NR' B=None -> MATCH: both absent`; `A='7' B=None -> MISMATCH: one absent, one '7'`.
- **What goes wrong:** an arm whose field ended `contract_unmet`, `declined`, unresolved, withdrawn
  or out of scope (the reader's `value=None`) agrees with an arm that reported the sentinel `NR`
  (MATCH, and an agreeing ABSENT label in kappa) and disagrees with an arm that reported a value
  (MISMATCH, a row in `disagreements.csv`). An engine/contract failure becomes a rater's answer in
  both the verdict rate and kappa; the report cannot tell "paper does not report it" from "the
  extractor produced nothing".
- **Refutation tried:** looked for a state check between reader and scorer — there is none;
  `load_arm` discards `ev.state`. `tests/test_concordance.py::TestScorePairNulls::test_nr_vs_none`
  pins `NR` vs `None` = MATCH at `score_pair`, where `None` meant "absent"; nothing pins it for a
  non-value state. Grepped the plan for `align_arms` / `run_concordance`: no ruling accepting it.
- **Tests:** `tests/test_non_value_tokens_downstream.py::test_site5_terminal_states_are_dropped_from_the_arm`
  states the purpose ("A CONTRACT_UNMET scored against another arm's real value is a MISMATCH that
  means nothing") and asserts only `load_arm`'s dict; it never runs the dict through `align_arms` /
  `score_pair`, where the MISMATCH it names is produced anyway.
- **Existing row:** new
- **Proposed class / package:** 1 / P5 — agreement statistics count engine non-values as answers.

### L14-C6 — the CI is not the Fleiss (1981) SE the code and CLAUDE.md name
- **File / function:** `engine/analysis/metrics.py::cohens_kappa`
- **Pattern:** i (comment "Analytical SE (Fleiss, 1981)"; CLAUDE.md "Fleiss-1981 SE with 95% CI")
- **Evidence level:** reproduced (the behaviour); the attribution by reading the formula
- **Evidence:** `se = math.sqrt(p_o * (1.0 - p_o) / (n * (1.0 - p_e) ** 2))` — Cohen's 1960

  terms this omits. Repro C4: n=2 perfect agreement `CI=[1.0, 1.0]`; n=2 total disagreement

- **What goes wrong:** the published interval is zero-width whenever `p_o` is 0 or 1, at any n,
  and can leave [-1, 1]; the method label in the docs is wrong.
- **Refutation tried:** the comment says the formula was kept deliberately so superseded and new
  figures share a CI method — that keeps the formula, not its name.
- **Tests:** `tests/test_concordance_pipeline.py::TestCohensKappa::test_ci_bounds` asserts only
  `ci_lower <= kappa <= ci_upper`; `tests/test_kappa.py` checks kappa against sklearn, never the CI.
- **Existing row:** new (B4 is the three kappa implementations)
