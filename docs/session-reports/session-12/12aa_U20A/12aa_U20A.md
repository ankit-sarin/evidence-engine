## §3 Mechanism at HEAD (3b)

**The ceiling** (`effective_ceiling`, 345–353):

```python
trained = n_ctx_train(model)
num_ctx = _option(options, "num_ctx")
if num_ctx is not None:
    return min(trained, num_ctx)
terms = [trained, SERVER_DEFAULT_CTX]
env = server_context_length()
if env is not None:
    terms.append(env)
return min(terms)
```

- **Read:** the trained context from `show`'s `modelinfo` (one key ending `.context_length`); `options.num_ctx` from the request; `OLLAMA_CONTEXT_LENGTH` from two paths under `/etc/systemd/system`, on every call, uncached; a constant.
- **Not read:** `show`'s `parameters` or `modelfile`. The row holds at HEAD.
- **Cached:** the trained value only, by `(digest, model)` under a run and `(host, model)` outside one (252–255). One `show` per key.

**The checks.** Before the call: `estimate_low >= ceiling` raises `InputOverflow`, nothing sent. After the call: `count >= ceiling` raises `InputTruncated`; `count < chars * RATIO_DROP` raises `InputDropped`; a missing count logs `input_fit UNVERIFIED` and returns.

**What is written.**

| Outcome | `run_calls.outcome` | Paper |
|---|---|---|
| Passes | `completed` | extraction proceeds on the response |
| `InputTruncated` | `refused_input_truncated` | `input_exceeds_context` / `input_truncated_at_ceiling` |
| `InputDropped` | `refused_input_dropped` | `input_exceeds_context` / `input_dropped_below_floor` |
| `InputOverflow` | `refused_input_overflow` | `input_exceeds_context` / `input_overflow_estimated` |
| `CeilingUnavailable` | `refused_ceiling_unavailable` | a **run fault** (`run_fault_classes`), not a paper outcome |

**Logged only:** the `ceiling` used. `fit` and the `input_fit` line carry it; `run_stage_configs` and the pin do not.

**What the manifest records about `num_ctx`.** `recorded["num_ctx"]` is `"unset"` with source `modelfile_or_server` at every stage but `vision_parse`. A Modelfile's value is recorded nowhere as a value. It is covered only through `model_digest` (F2).

**Under a run, the digest guards a mid-run change.** `ollama_chat` calls `check_call_digest` before the input-fit read, and a changed digest raises `ModelDigestChanged`.

**The service term (N25).** `server_context_length` reads files. The comment at 154–156 states why: "Read as files — the drop-in is where this host keeps Ollama's environment — never through systemctl, which the test suite's service-call fence refuses by design." U19's `read_ollama_env` reads `systemctl show` (the loaded unit configuration). So three different things now exist: the files (the ceiling), the loaded configuration (the U19 record and check), and the running process (neither).

**Row against code.** The row's "three terms (trained context, options.num_ctx, service env)" omits a fourth, `SERVER_DEFAULT_CTX`. F7. Otherwise the row and the code agree.

## §8 Findings

**F1 — N25's owner is stated two ways.** The row says "with U19: the ceiling's service term reads unit files, not the running server". R734(d)(ii) says "N25 (`server_context_length` reads unit files) stays as designed and is U20's." The U20 entry names only "**Rows:** INT-i12-11", and N25 has no acceptance test. The ruling is later and governs, so N25 is U20's. What U20 must do about it is not stated anywhere. "Stays as designed" can be read as "no change", which is N4.

**F2 — The digest question the §4 row left open is answered by structure (2e.1).** The row says "whether that also changes the /api/tags digest the pin records was not checked". `evidence/modelfile_params_on_disk.txt`: "20 manifests; digest==sha256(manifest file) 20/20", and 18 of the 20 manifests carry a params layer by digest. A changed `num_ctx` is a different params blob, so a different manifest, so a different digest. **This is inferred from the structure and not exercised:** no model was created. If it holds, cases 5 and 6 are refused today, and the row's live condition narrows to **case 7**: a Modelfile value present when the arm first pins. On that reading a "during the run" trigger, in the §4 row's words, is closed by U18.

**F3 — The trigger is absent on all 20 installed models, re-measured 2026-10-30 (2e.2).** The entry's note reads "neither `deepseek-r1:32b` nor `gemma3:27b` sets `num_ctx`", dated 2026-10-11. By file read: `has_num_ctx False` on 20 of 20. The service: `systemctl show` carries no `OLLAMA_CONTEXT_LENGTH` (count 0), and the journal's server-config line reads `OLLAMA_CONTEXT_LENGTH:0` this boot. Readings of a day, not invariants.

**F4 — The server does state the context it loaded, and on this runtime (2e.5).** `ProcessResponse.Model` has `context_length: Optional[int] = None`, and committed run summaries show it populated on Ollama 0.21.0: `evidence/ps_context_length_prior.txt`, "('gemma3:27b', 131072)", "('qwen3:8b', 40960)" (`docs/session-reports/screen-auth-2g/`, 2026-09-19 and -20, `"ollama_version": "0.21.0"`). Nothing in the engine reads it. Its response to a Modelfile `num_ctx` is not measured (§9 Q3).

**F5 — The file read is an addition to the brief's reads.** The brief bars an Ollama request other than version, tags or ps, and "Any Modelfile read through the server". It does not name a file read of the store. I read manifests and `params` blobs as files because that answers 2e.1 and 2e.2 without any server request. If this exceeded the brief's intent, the conclusions in F2 and F3 are the ones to discount.

**F6 — "The fix is one term" is understated (2e.7).** The entry says "the fix is one term". The term's value is a free-text string that has to be parsed: `parameters: Optional[str] = None`. `n_ctx_train` returns one int and caches one int (`dict[tuple[str, str], int]`), so the cache's value or a second cache changes. Absent, empty and unparseable each need a stated outcome. An absent value must not be a failure: two models have no params layer. The `min` is a statement about runtime precedence (Q1). Still `engine/utils/ollama_client.py` only, as the entry's Files line says.

## §9 What could not be established read-only

**Q1 — Does a Modelfile `num_ctx` outrank `OLLAMA_CONTEXT_LENGTH`?** Decides whether `min` is the runtime's rule or only a conservative bound. A wrong `min` gives false refusals, not silent cuts. Answering it needs a model created with the parameter, and a load. Barred here.
