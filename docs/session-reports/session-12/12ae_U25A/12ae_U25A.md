## §3 Mechanism at HEAD (3b)

1. **YAML 1.1 under PyYAML 6.0.3's `safe_load`** (CODE ORDER, the installed resolver, `.venv/lib/python3.12/site-packages/yaml/resolver.py:171–175` and `:201–205`):
   - `'tag:yaml.org,2002:bool'` matches `^(?:yes|Yes|YES|no|No|NO|true|True|TRUE|false|False|FALSE|on|On|ON|off|Off|OFF)$`.
   - `'tag:yaml.org,2002:null'` matches `^(?: ~ |null|Null|NULL | )$`, the empty scalar included.
   - Bare `y` / `n` are **not** in the bool pattern in this version, so they stay strings.
   - Only plain (unquoted) scalars are resolved implicitly; a quoted `"No"` is always a string.
   - The same resolver list also carries `int`, `float` and `timestamp`, so an unquoted `1`, `1.5` or `2026-03-15` becomes a non-string too (§8 F3).
2. **Where a check can sit** (CODE ORDER). Between `:448`'s `yaml.safe_load` and `:460`'s model build. `_validate_valid_values` already walks every entry (`:350` `for item in vv:`), and `_validate_top_level` already holds `doc["absence_sentinels"]` (`:262`). Both have the path and the field's `where` in scope for a message.
3. **The semantic hash** (CODE ORDER, FAKE). `json.dumps(…, default=str)` over the parsed document. A bool hashes as JSON `true`/`false` and `None` as `null`. Only the quoted text yields `"Yes"`. So the same visible word hashes differently quoted and unquoted. FAKE: each scratch variant's hash differs from the live file's.
4. **The frozen-codebook constraint** (FAKE). The live file loads, and its semantic hash `f261af76feadd650f3c58b36498e2d140ef2dc4ffec6a80a16c06741eb2f5646` equals the recorded value. Option A's check, run over the live document, reports no finding. Option B's loader parses the live text to a document equal to `safe_load`'s, so its semantic hash is equal too. E3 holds for both.

## §7 Options (3f) and classified sites (3g)

**Option A — a type check after `safe_load`, refusing any non-string `valid_values` value or sentinel, naming the key and saying to quote it** (the entry's form).
- **Sites:** `_validate_valid_values` (`codebook.py:350–371`, inside the existing loop) and `_validate_top_level` (`:262–275`, beside the existing list check), or one new pass called from `_parse` after `:453`.
- **Tests:** the new acceptance test only (§4: no fixture moves).
- **Frozen codebook:** the live load and its semantic hash are unchanged (FAKE, §3 point 4).
- **A second review:** a hand-written codebook is refused loudly.
- **What it does not fix:** the other rendered string fields (§6), and whatever a numeric scalar does unless the check is "not a str". It keeps YAML 1.1 parsing, so authors must still quote.

**Option B — a custom SafeLoader without the bool and null implicit resolvers, for the codebook document only.**
- **Sites:** `_parse`, `:448`: `yaml.safe_load(text)` becomes `yaml.load(text, Loader=<the codebook loader>)`. The loader class is defined in `codebook.py`. FAKE: removing the two resolvers from a `SafeLoader` subclass.
- **Tests:** the entry's test as written ("each raises at load") does **not** hold under B, because B accepts `Yes` as the string `"Yes"`. The acceptance test would have to be rewritten as "each loads as the string written", which is a different discharge of R587.
- **Frozen codebook:** the live parse is equal to `safe_load`'s and the hash unchanged (FAKE).
- **A second review:** silent, but correct. Nothing is refused.
