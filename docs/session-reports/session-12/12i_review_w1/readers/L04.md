### L04-C4 — `open_run` commits a caller's open transaction, against its own "nests inside a caller's open transaction" comment

- **Pattern:** iii
- **Evidence level:** reproduced (mechanism, on a synthetic table) / code order for `open_run` itself
- **Evidence:**

  # A savepoint, not BEGIN: it nests inside a caller's open transaction instead
  # of failing on it, and RELEASE commits when it is the outermost.
  conn.execute("SAVEPOINT open_run")
  ...
      conn.execute("RELEASE open_run")

- **Refutation tried:** read each production call site: `import_extraction_entry` runs `ensure_workflow_table(conn)` ("Its executescript commits, so it runs before the transaction opens") first; the other two write nothing before.
