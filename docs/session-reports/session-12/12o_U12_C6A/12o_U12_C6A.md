## 5. Options

R639(c) confines the mechanism to `engine/cloud/__init__.py`, with the extractor modules keeping their module-level imports. Each option is stated with its five properties.

**Option A — the re-exports removed.** `engine/cloud/__init__.py` keeps its docstring and imports nothing.
- **Files:** `engine/cloud/__init__.py` only. Importers to repoint: **none.** The census finds no importer of a package-level name, and no untracked or ignored file names the package.
- **Pin effect:** none (§4, evidence (a)–(c)).
- **Collected-count delta of the mechanism:** **0** (§4: no script changes; the 7 `engine.cloud` parity cases name submodules).
- **Migration 014:** byte-identical. It is loaded by `importlib.import_module` (`runner.py:309`), so the change reaches it through the package it imports.
- **Acceptance test (R639(c)):**
  - (i) A fresh `ReviewDatabase` constructed with both SDKs blocked succeeds and records all 18 schema migrations.
  - (ii) `engine.cloud.schema` and `engine.cloud.base` import with both SDKs blocked.

  - (v) `pin_tuples.py` output is byte-identical.
  - (i) and (ii) need a fresh interpreter, because in the pytest process the SDKs are already in `sys.modules` (`test_cloud_extraction.py:11–12`). So they run as a subprocess of `.venv` python, which the suite fence does not refuse (it matches service managers and privilege escalation only).
  - The acceptance test adds its own cases to the collected count. That delta belongs to the test, not the mechanism; Phase B's brief states it.
- **What a cloud entry point does with an SDK absent:** `run_cloud_extraction.py:25` and `:27` import the extractors at module level, so the script fails at import with `ModuleNotFoundError` naming the SDK. R639(b) accepts that.

**Option B — a module `__getattr__` (PEP 562).** `__init__.py` keeps the three names available as package attributes. A module-level `__getattr__(name)` imports the owning submodule on first access to `AnthropicExtractor`, `OpenAIExtractor` or `init_cloud_tables`, and raises `AttributeError` for anything else.
- **Files:** `engine/cloud/__init__.py` only.
- **Pin effect:** none (as A).
- **Collected-count delta of the mechanism:** **0** (as A).
- **Migration 014:** byte-identical (as A).
- **Acceptance test:** A's (i)–(v), plus one case that `engine.cloud.AnthropicExtractor` and `engine.cloud.init_cloud_tables` still resolve through the package.
- **What it costs:** about ten lines that keep an interface **no importer uses** (§2). R31's test — retain only what serves the engine going forward — is not met by a re-export with zero callers. A `__getattr__` is also invisible to the AST census and the inventory tool: a later `from engine.cloud import X` would work without appearing as an import of the package's own code.

**Option C — schema eager, extractors removed** (a variant of A, stated for completeness). `__init__.py` keeps `from engine.cloud.schema import init_cloud_tables` (SDK-free) and drops the two extractor lines.
- **Files:** `engine/cloud/__init__.py` only.

- **Acceptance test:** as A.
- It keeps one re-export that the census also finds unused. It differs from A only in loading `schema` whenever any `engine.cloud` submodule is imported. That costs nothing, but it buys nothing either.

**Recommendation: A.** Measured importers of package-level names: 0. Collected-count delta: 0 for every option. The pins don't distinguish the options either. A is the smallest change, leaves nothing that serves no caller, and a future need for a package-level name fails loudly (`ImportError`) rather than silently.
