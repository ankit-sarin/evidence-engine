## 1. audit_run (2(a))

`engine/agents/audit_events.py::audit_run(conn, spec, *, run_id, arm, review_dir)`; its one production
caller is `scripts/run_pipeline.py::_stage_audit` (`audit_run(db._conn, spec, run_id=run_id,
arm=spec.extraction_models.arm, …)`).

**Selection.** The eligibility axis and the arm's claims, and nothing else:

```python
    for pid in eligible_paper_ids(conn):
        claims = live_claim_events(conn, pid, arm, event_types=("asserted",))
        if not claims:
            continue
        done = {ev.claim_id for ev in live_claim_events(
            conn, pid, arm, event_types=("citation_located",))}
        todo = [c for c in claims if c.claim_id not in done]
        if not todo:
            continue
```

The processing axis is not consulted for selection. It is read once, after locating and verifying, and
only to stamp `from_state`: `processing = effective_state(conn, pid).processing`.

**Order.** Select (above) → resolve the claims' text (`ref = claim_text_ref(conn, todo)`; `text =
read_parsed_text(ref)`) → locate every todo claim and verify the unlocated, populated ones with a
supplied snippet (no transaction held across the model call) → `effective_state` → one savepoint
writing every `citation_located` event, every verdict row and the `audited` paper event.

**The write:**

```python
            write_paper_event(
                conn, event_type="audited", paper_id=pid, to_state="audited_ai",
                from_state=None if processing == NO_RECORDED_STATE else processing,
                actor_kind="engine", actor_role="system", actor_name="auditor",
                actor_digest=auditor_digest, run_id=run_id, stage_name="audit",
                payload={"arm": arm, "located": located,
                         "not_located": len(results) - located,
                         "locator_version": LOCATOR_VERSION,
                         "parsed_text_sha256": ref.sha256}, commit=False)
```

No `reason_code` is passed. The 019/022 CHECK forbids one on a non-failure token (§2).

**Skip branches.**
- No live asserted claim of the arm → `continue`, nothing written.
- Every claim already located → `continue`, nothing written.
- The claims' text refused (D23: `except (ParsedTextError, _ClaimTextRefused) as exc:`) → a WARNING log
  line naming paper, reason code and text uid(s), the paper added to `AuditReport.skipped_refused`,
  nothing written. D22's `audit_not_possible` event is unbuilt (023).
- The all-unmet / all-declined case: `audit_run` selects only `event_types=("asserted",)`, so a paper whose
  every claim is `contract_unmet` or `declined` has no `asserted` claim and is skipped by the first
  `continue`, with nothing written.

**"Reason cleared" (I3).** No column is written NULL by an update; `paper_events` is append-only. The
`audited` event carries `reason_code` NULL as the CHECK requires. The reader then takes the last
processing-axis event (`processing, proc_prov = to_state, prov`) and sets `reason = reason_code if
is_failure(to_state) else None`, so the failure's reason leaves the paper's derived state while the
failure event keeps its own `reason_code`. I3 holds in that sense: the clearing is the reader's, from the
NULL the CHECK forces on the new event.

**`analysis_ready`.** `EffectiveState.analysis_ready` is `self.eligibility == "eligible" and
self.processing in COMPLETED_PROCESSING_STATES`, with `COMPLETED_PROCESSING_STATES = ("extracted",
"audited_ai")` in `engine/core/paper_state.py`.

## 2. The processing axis (2(b))

Vocabulary (`engine/core/paper_state.py`), the one declaration:

- `PROCESSING_STATES = ("parsed", "extracted", "extraction_failed", "full_text_not_obtainable",
  "parse_failed", "input_exceeds_context", "audited_ai")`
- `FAILURE_STATES = ("extraction_failed", "full_text_not_obtainable", "parse_failed", "input_exceeds_context")`
- `COMPLETED_PROCESSING_STATES = ("extracted", "audited_ai")`
- `NO_RECORDED_STATE = "no_recorded_state"`

The database's copy is migration 022's rebuild of `paper_events` (`paper_events_sql`, re-declaring the
tokens; R35: migrations do not import `paper_state`). Read from a fresh scratch database
(`paper_events_ddl.txt`):

```sql
        to_state    TEXT    NOT NULL CHECK (to_state IN ('eligible', 'abstract_out', 'full_text_out', 'parsed', 'extracted', 'extraction_failed', 'full_text_not_obtainable', 'parse_failed', 'input_exceeds_context', 'audited_ai')),
        ...
        CHECK (
            (to_state IN ('extraction_failed', 'full_text_not_obtainable', 'parse_failed', 'input_exceeds_context') AND reason_code IS NOT NULL)
         OR (to_state NOT IN ('extraction_failed', 'full_text_not_obtainable', 'parse_failed', 'input_exceeds_context') AND reason_code IS NULL)
        ),
```

The triggers are `paper_events_no_delete` and `paper_events_no_update` (append-only). **No CHECK and no
trigger constrains the transition**: `from_state` is a free TEXT column. I2: the vocabulary lives in
`paper_state.py` and in 022's DDL, not in `engine/core/events.py`.

**Resolution.** `effective_state` walks the paper's events in `event_id` order and takes the last token on
each axis. A later `audited_ai` therefore replaces an earlier `parse_failed` unconditionally. No state is
terminal on the processing axis.

**Writers.** `engine/core/events.py::write_paper_event` is a bare INSERT (`"INSERT INTO paper_events
(event_uid, event_type, … to_state, from_state, reason_code, stage_name) VALUES (…)"`); it checks the run
link and nothing about the prior state. It refuses `audited_ai` from no state.

## 5. The D22 boundary (2(e))

D22 (R431, 023 unbuilt): `audit_not_possible` is "a new processing-axis failure state … one paper event
with a reason code, not analysis-ready", for "the claim's text version missing, altered, without a ref row,
not recorded, and claims spanning text versions" (R439). Today those cases are `audit_run`'s D23 skip:
logged, `skipped_refused`, no event.

**Proposed rule.** U15's guard is a **selection rule on the processing state**: which papers the audit stage
admits. D22 is the **outcome for an admitted paper the audit could not complete**. The two do not overlap:
the guard decides before the text is resolved; D22 records what happened after.

Placement of §4's triggers: none falls on the wrong side. The D24 and D21 cases leave no live claim, so
neither the guard nor D22 sees them. A paper at `audit_not_possible` (once 023 lands) with its condition
later cleared must be re-admitted by the next audit, or it can never leave that state. **The admitted set
must therefore include `audit_not_possible` once that token exists**, and a write guard (§10 (B)) must allow
`audit_not_possible → audited_ai`.

## 8. Pin effect (2(h), R608)

The pin tuple (`engine/core/run_manifest.py::pin_tuple`) holds `arm_kind`, `provider`, `model`, the arm's
own `stages` (model, model_digest, options_hash, format_schema_hash, prompt_hash), `codebook_hash`,
`client_library` and, for a unit-citing arm, `segmentation` (12s_U14A §7). The `audit` stage is not the
arm's stage and is not in the tuple. A selection guard in `audit_run`, or a write guard in
`write_paper_event`, changes no prompt, option, stage set, codebook or library. **No pin effect.**

## 10. Options — PROPOSED

**Admitted set.** `extracted` (a stored extraction, the normal case) and `audited_ai` (idempotent: a paper
already audited that somehow holds new unlocated claims). Once 023 lands, also `audit_not_possible`, so a
paper whose refusal clears can be audited. `no_recorded_state`, `parsed` and the four failure tokens are not
admitted.

- **(A) Selection guard.** `audit_run` reads `effective_state(conn, pid).processing` before resolving the
  text, and skips a paper outside the admitted set. The skip writes a WARNING log line naming the paper,
  its state and its reason, adds the paper to the report, and, until 023, writes no event.
  - Changes: `audit_run`'s selection; `AuditReport` gains a skipped-by-state list.
  - Fixes: F3 for every path, F6 included.
  - Risks: (i) F9's fixtures audit `no_recorded_state` papers; they must record an `extracted` event first
    (a fixture change, no change of intent). (ii) A paper skipped for its state is reported but carries no
    event until 023, so PRISMA counts it under its failure, which is correct.
  - Pin effect: none.
- **(B) Write guard.** `write_paper_event` (or an `audited`-specific check beside it) refuses
  `to_state="audited_ai"` when the paper's current processing state is outside the admitted set, raising a
  loud, `RunRefused`-class error inside the audit's savepoint.
  - Changes: the writer.
  - Fixes: F2 as an invariant of the store.
  - Risks: the audit's savepoint rolls the paper back and the run stops on it unless `audit_run` also
    selects around it, so (B) alone turns a silent defect into a run fault. A write guard must also allow
    `audit_not_possible → audited_ai` once 023 exists (§5), or 023's paper can never recover. A guard keyed
    on the current state must read `effective_state` inside the writer, which today reads nothing.
  - Pin effect: none.
- **(C) Both.** The writer refuses as the invariant; the selection skips as the behaviour, so the refusal
  never fires on the pipeline and a future writer that bypasses selection fails loud.
  - Risks: two copies of the admitted set unless one owns the predicate and the other imports it (one
    predicate in `paper_state.py`, e.g. `AUDIT_ADMITTED_STATES`).
  - Pin effect: none.

**What the triggers favour (PROPOSED).** §4's reachable paths leave nothing for a guard to catch, and the one
demonstrated route (F6) is a selection bypass. (A) is the behaviour U15 needs; (C) is worth its second
check only if the PI wants the store to hold the invariant against writers not yet written (023's
included). (B) alone is not enough.

## 11. Acceptance tests — PROPOSED

1. (§6, each failure token) A paper at `parse_failed`, `extraction_failed`, `input_exceeds_context` or
   `full_text_not_obtainable` with live unlocated claims is **not** audited. Its processing state and reason
   are unchanged, `analysis_ready` stays False, and no `citation_located` or `audited` event is written.
2. (§6) The same for `parsed` and `no_recorded_state`.
3. (§6 control) A paper at `extracted` is audited as today: `audited_ai`, `analysis_ready` True.
4. (PRISMA) After an audit over a mixed corpus (one `extracted`, one `parse_failed`, each with claims),

5. (the log) The skipped paper's WARNING line names its id, state and reason, and the report lists it.
6. (§4 `same_key`) A same-key failure written over live claims leaves the paper at `extraction_failed` after

7. (if (B) or (C)) Writing `audited_ai` over a non-admitted state raises the named refusal, and the

8. (§4 `d24_reparse`, `d21_refusal`) unchanged: the failure supersedes the old-key claims, and the audit
