## Answer

1. **Readers.** No engine, analysis or script code reads `state_at_write`. The only keyed reads are in three
   test files, and one committed 12g analysis script tabulates it. No export, no methods text and no judge
   path reads it.
2. **The writer's rule.** `engine/core/events.py`, `write_field_event`, stamps it on every field event from
   the event type alone, with the citation list hard-coded empty. For an `asserted` event the label is
   therefore always "asserted without locatable evidence", on both extraction paths.
3. **Expectation check.** Both expectations of the brief held: the label is set at extraction time, before
   any location; and there is no export, methods or judge reader.

## Sources read (quoted at HEAD, by path and function)

**The writer** — `engine/core/events.py`, `write_field_event`:

```python

                       classify_field_state(value, [], event_type, sentinels=sentinels))
    payload.setdefault("rule_version", RULE_VERSION)
```

`setdefault`, so a caller could pre-set the key; no caller does (census A below: outside this line the token
appears in engine code only in two module docstrings).

**The rule it calls** — `engine/core/effective.py`, `classify_field_state`:

```python
    if event_type == "declined":
        return DECLINED
    if event_type == "contract_unmet":
        return CONTRACT_UNMET
    if event_type != "asserted":
        return None
    located = any(bool(c.get("located")) for c in citations)
    return ASSERTED_WITH_EVIDENCE if located else ASSERTED_WITHOUT_EVIDENCE
```

With `citations` fixed at `[]`, `located` is always false. The label is a function of `event_type` only:

| event type | label written |
|---|---|
| `asserted` | `"asserted without locatable evidence"` |
| `declined` | `"declined"` |
| `contract_unmet` | `"contract unmet"` |
| any other (`citation_located`, `superseded`, reviewer events) | `null` |

**Why it cannot be otherwise today.** `citation_located` has one write site, `engine/agents/audit_events.py`,
`audit_run`, which runs at the audit stage, after the claim exists (row B7 and its 12d note: "`citation_located`
has one write site, `audit_run`; the elicited path makes no `locate` call"). This holds for the two-pass path as
well as the elicited one: neither locates at extraction.

**The reader's stated contract** — `engine/core/effective.py`, module docstring:

> "The writer records its own verdict in `payload_json.state_at_write` as telemetry a test asserts the derivation
> against; the reader does not consult it."

**The test that names the behaviour** — `tests/test_effective_reader.py`,
`test_rule_v21_a_later_located_event_moves_the_state_off_state_at_write`:

> "Not a divergence: the writer's verdict is true at write time, and a citation_located arriving afterwards is

**What exports and the judge read instead.** They read the *derived* state and the located payload:

- `analysis/paper1/judge_loader.py`, `_fetch_spans_for_paper` and `load_grid`: `ev.provenance.get("located")`

`ev.state` comes from `engine/core/effective.py`, `_classify_claim`, which calls `classify_field_state` with the
claim's real `citation_located` payloads (`_citations_for`). It does not touch the stored label.

## PROPOSED class and package

**PROPOSED: Class 3, package P7** (telemetry and wording). CC proposes; the PI rules.

The stored label cannot make a stored result, its provenance or a human gate wrong, because nothing reads it and
the reader derives state from the citation events. What remains is a name that invites misreading: on a located
claim the payload still says "without locatable evidence", and it will say so on every Run 7 claim. Two ways to
close it, neither pin-affecting (the payload is not part of the arm pin, R539):

- (a) keep the key, and state in the `write_field_event` docstring and the `effective.py` module docstring that
  the label is the state at the instant of writing and is always the unlocated form for an `asserted` event;
- (b) stop writing the key for `asserted` events, or rename it, and move the three tests to the derived state.
  This changes what a fresh run writes into `payload_json`, so it lands before the freeze smoke for the same
  reason any payload change does: the freshman state should write what Run 7 writes.

CC's PROPOSED choice is (a): two docstring sentences, no test churn, no payload change.
