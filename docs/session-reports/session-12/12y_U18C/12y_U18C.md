# 12y-U18C — U18 commit 2: the model digest re-checked on every call under a run (R721(b), R726(d), R727)

## §0 HEAD and scope

- Parent: `2c67bfcdee68f2b93345897c8f79ede512d8bbf1`, the item-0 commit (R723–R726 as Blocks 121–124;
  ledger `fbfdda4`). Commit 1 is `e7425b3`.
- Under an active run, `ollama_chat` reads the model's current digest before each call. It reads through
  the `digest_fn` the run was opened with: production's is `fetch_model_digest`, through the engine
  client; a test's is the one it injected.

- The trained-context cache is keyed by the digest the check read.
- No request byte, arm pin or `prompt_hash` moves (§6). No live write and no model call.
- The brief and its resume: 12y-U18C, and R727, a ruling on the 0c stop (the close path; the registry;

## §1 What changed, file by file (quoted before → after)

**`engine/core/run_manifest.py`**

- **New class** `ModelDigestChanged(RunRefused)`, beside its siblings:
  - It is constructed from a message, as every `RunRefused` is (`RUN_REFUSED_MEMBERS` builds each member
    as `c("refused")`), with keyword fields `stage_key`, `model`, `recorded` and `current`.
  - `ModelDigestChanged.at(stage_key, model, recorded, current, detail=None)` composes the message, which
    starts with the class name, so `str(exc)` and the close's `end_reason` both start
    `"ModelDigestChanged: "` (E1 together with E5). The message names the stage key, the model and both
    digests, and says what to read: `ollama list`, and the journal for a pull or create.
- **New registry** `_RUN_DIGEST_FNS: dict[tuple[str, int], Callable[[str], str] | None]`, keyed
  `(_database_file(conn), run_id)` like `_RUN_ARM_TUPLES` (E3, R727(d)).
  - It is written at `open_run`'s success: after `_RUN_ARM_TUPLES[(_database_file(conn), run_id)] =
    carried` comes `_RUN_DIGEST_FNS[(_database_file(conn), run_id)] = digest_fn`.
  - Nothing clears `_RUN_ARM_TUPLES` (grep: its only writer is that line and its only reader is
    `bind_extraction_arm`), so nothing clears this one either.
  - A run with no entry, opened without `open_run` (M3's test affordance), has no check.
- **New function** `check_call_digest(stage, model)`:
  - Outside a run, for a call with no stage, or for an unregistered run, it returns `None`.
  - Otherwise it reads through the registered `digest_fn`, or `oc.fetch_model_digest` looked up at call
    time when that is `None`, and compares with `stage_digest(conn, run_id, call_stage_key(stage,
    model))`. On a difference it raises `ModelDigestChanged.at(...)`, and on a match it returns the digest.
  - A `ModelDigestError` caused by `ConnectionError`, `httpx.ConnectError` or `httpx.ConnectTimeout` is
    re-raised as that cause, so a down server stays the run fault it was (R532). Any other unreadable
    digest (a tag removed mid-run, a malformed answer) raises `ModelDigestChanged` with
    `current=None`.

## §3 The raise-to-close path (E8), as read and as it runs

**As read at 0c** (R727(a)'s cause):
- The only 'aborted' close on a model-calling runner was `run_pipeline`'s `except RunAborted`.
- `RunAborted(RuntimeError)` is not a `RunRefused`, so a `RunRefused` raised in `ollama_chat` reached
  `except Exception` and closed 'failed' with `failure_reason(exc)`.
- The FT runner closed 'failed' for any exception.
- The brief named the close, not the files that hold it.

**As built:**
1. `ollama_chat` raises `ModelDigestChanged` before `_check_input_fits` and before `_record`, so there is no
   `run_calls` row (C54's form).
2. It is a `RunRefused`, so `is_run_fault` re-raises it ahead of every converting handler on the extract
   path. `test_run_fault_predicate.py`'s two `[ModelDigestChanged]` ids assert this.
3. **`scripts/run_pipeline.py`** catches it in its own clause → `_finish_review_run(db, run_id, "aborted",
   reason=str(exc))`, then re-raises (`test_u18_run_pipeline_closes_aborted_on_a_digest_change`).
4. **`engine/agents/ft_screener.py::run_ft_invocation`** catches it → `rm.close_run(…, "aborted",
   reason=str(exc))`, then re-raises (`test_u18_the_ft_runner_closes_aborted_on_a_digest_change`).

The import paths make no model calls and are unchanged.

## §4 The preflight, the `digest_fn` carriage, the cache key

- **The preflight (I6).** `resolve_run` digests each preflight model under `preflight:<model>`, and the
  check compares against `stage_digest(conn, run_id, call_stage_key("preflight", model))`. On a fresh run
  the two are equal and the probe is sent
  (`test_u18_the_preflight_call_is_not_refused_on_a_fresh_run`).
- **`digest_fn` (I2, R727(d)).** It is carried in `_RUN_DIGEST_FNS[(database file, run_id)]`, not on
  `RunHandle` (a frozen dataclass, unchanged). The database file is in the key because per-test databases
  all number their first run 1, and a bare run_id would hand a later test an earlier test's function.
  `None` means `fetch_model_digest` at call time, so production reads through the engine client (U18
  commit 1's keep-alive route).
- **The cache.** The key is `(digest, model)` under a run and `(host, model)` outside one. A replaced tag
  under the same name gets its own entry, and the same digest on another host shares one
  (`test_u18_the_context_length_cache_is_keyed_by_digest`).

## §7 Findings

1. **The check-to-send window is a recorded limit** (R721(b)). The digest is read immediately before the
   input-fit read and the send. A tag replaced after the read and before the server loads the model for
   that call is not seen. Neither is a replacement during a call, or across the last-resort restart's
   retry (`_restart_ollama_and_retry` resends without re-checking). Not tested, as ruled.
2. **`ModelDigestChanged` is not an `open_run` refusal.** CLAUDE.md's refusal list (:344) is `open_run`'s,
   so the class is described with `ollama_chat`'s behaviour instead (§1). The brief's 3d read as though it
   belonged in that list; the record governs.
3. **A down server stays a run fault.** `fetch_model_digest` wraps a refused connection as
   `ModelDigestError`, which is not in `run_fault_classes()`. Unhandled, the per-call check would have
   turned an unreachable server into a paper outcome (an `extraction_failed` event, counting toward the
   abort), changing R532. The check re-raises the transport cause instead. An unreadable digest for any
   other reason is refused as `ModelDigestChanged` with `current=None`. This was not in the brief; it is
   the reading that keeps R532 true.
4. **E1 and E5 together fix the message form.** E1 sets `reason=str(exc)` and E5 requires a reason
   starting with the class name, so the class's message begins `"ModelDigestChanged: "`. The other
   `RunRefused` messages begin `"run refused: "`.
5. **The `RUN_REFUSED_MEMBERS` pin also pins a constructor convention**: every member is built from one
   message (`c("refused")`). The first form of the class (four positional fields) failed it; the class now
   follows its siblings, with an `at(...)` factory.
6. **R117's comment no longer describes production.** The three fixtures that fail `fetch_model_digest`
   "during a run" (`test_extraction_run_link.py`: "T5: the run never fetches a digest of its own (R117)")
   stay green because they inject `digest_fn`. Production now does read a digest during a run, once per
   call, through the run's own function (R721(b)).
7. **The six stops of U18** (R725(e)'s list plus this one), one cause: scope predicted from a description
   instead of read from the record.
   1. 12y-U18B 0d: the Touched list omitted four seam tests (R722).
   2. Item 0: "−" exactly 3 (R723).
   3. 0e: twelve whole-function fakes (R723).
   4. Step 2: a manifest shape pin (R724).
   5. The first gate: a module-alias patch and a membership pin (R725).
   6. 12y-U18C 0c: the 'aborted' close lived in two files outside the Touched list (R727(a)).
