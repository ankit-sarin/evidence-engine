## 3. Where the checks fire

**At spec load** (`ReviewSpec`): `_lineage_tokens` refuses a value outside `LINEAGES`, naming the
entry and the vocabulary; `_lineage_covered` refuses any model `named_models()` returns without an
entry, naming each model and every field that names it — default factories included
(`audit.model`, `pdf_parsing.vision_model` on the live spec) and every model arm.

**At `open_run`**, in this order: run kind → `CodebookReviewMismatch` → `DirtyTree` →
`AmbiguousEngineState` → `CloudArmNotEnabled` → the arm registry (`PreManifestArm`, `RetiredArm`) →
**`ModelLineageMissing`, then `SameLineageVerifier`** → `resolve_run` (the digest fetch) →
`ArmPinMismatch` → payload description → `SAVEPOINT open_run` → the rows. The lineage check needs no
server, so it refuses before the digest is fetched; it is before the savepoint, so it writes nothing.
Coverage is re-checked over every declared stage's resolved model (preflight probes and cloud arms
included), because `model_copy` skips validation (12w_U17A §6 finding 6). When `audit` is declared,
each declared extraction stage's model is compared with the auditor's lineage. In an audit-only run
(`--skip-to audit`), the extractor's models come from the arm's pin
(`arms.configuration_json["stages"][s]["model"]`) when `configuration_marker` is `pinned`, else from
`stage_config` over `extraction_stages(spec)`; `lineage_check.extractor_source` records `"pin"` or
`"spec"`. Lineages always come from the current spec's map.

**Recorded** (R703(f) as R704(b) amends it): each `manifest_json.stages[<key>]` gains `"lineage"`; a run
that declares audit gains `lineage_check` = `{audit_model, audit_lineage, extractor_models,
extractor_lineages, extractor_source}`. No server-family key.

**R704(b)'s withdrawal, and its reason, recorded:** R703(c)'s sentence recording the server's family
string and R703(f)'s "and server family (or null)" are withdrawn — "the model digest the manifest
already records identifies the served weights exactly; the family string is never compared (R703(b))
and would add a field the rule does not use, at the cost of widening U17 into
engine/utils/ollama_client.py and the 15 test files that patch fetch_model_digest, or of a field that
always reads null."
