No schema change; the manifest body is unchanged except that `pins` no longer lists the local arm.

## What changed

- **`open_run`.** The local extraction arm (the arm of an `extract_*` / `elicitation_pass1` stage, unless also named in `arms=`) is deferred: an unregistered one gets an `arms` row with `configuration_marker` NULL, which the stage rows' foreign key needs; a pinned one is compared over the whole tuple as before, and a difference refuses the run naming the keys. `PreManifestArm` and `RetiredArm` are unchanged. Cloud arms and `arms=` arms pin at open as before.
- **`run_manifest.bind_extraction_arm(conn, run_id, arm=…)`**, new. With the tuple the run resolved at open: an unpinned arm is pinned (`pinned_run_id` this run; one UPDATE in a savepoint, committed); a pinned arm is compared over the whole tuple and a difference raises `ArmPinMismatch` naming every differing key. Nothing is resolved again.
- **`extractor.verify_extraction_run`** calls it, then `extraction_digest` as before. Both existing call sites therefore bind; the second call compares equal and writes nothing.
- **`extraction_digest`** is unchanged: it reads only, refuses an unpinned arm, and compares each stage's digest from the run's rows.
- **`scripts/run_pipeline.py`**: a comment at the extract stage. No behaviour of its own changed; it opens through `open_run` and reaches extract through `verify_extraction_run`.

## R509 findings (none Class 1)

- **F1 — the event writer accepts a claim on an arm that no run has pinned.** `events._refuse_claim_on_arm` requires only that the claim's run declared the arm (a `run_stage_configs` row). With pinning moved to the extract stage, a claim written between open and extract would land on an unpinned arm, and the freeze trigger would then refuse the pin for good. No engine path writes one there: the extractor writes after `verify_extraction_run`. `tests/test_extractor.py::test_staleness_skip` did exactly this through the fixture. `bind_extraction_arm` now turns the trigger's refusal into a named `ArmPinMismatch` ("cannot be pinned … declare a new arm name"). `events.py` is outside this unit. Proposed Class 2, P1: the writer refuses a model extractor's claim on an unpinned arm.
- **F2 — a run this process did not open gets the digest comparison only.** The whole-tuple comparison at extract needs the tuple `open_run` computed, which is carried in memory. A run opened in another process has none; `extraction_digest` still refuses an unpinned arm and compares digests. No engine path extracts under a run another process opened. Proposed Class 3, P7 (or: record the resolved tuple in the manifest body, which would make it durable).
- **F3 — a manifest no longer says which tuple its local arm resolved to.** `manifest_json.pins` listed the arm's pin sha when the manifest pinned it; it is now empty for a local extraction run, and `arms.pinned_run_id` names only the run that pinned. The per-stage hashes are still in `run_stage_configs`. Proposed: with F2, the same remedy.
- **F4 — `tests/_event_store_fixture.py::open_extraction_run` now reaches the extract-stage binding.** Its contract was "pins the spec's arm exactly as a production run would"; it calls `verify_extraction_run` after `open_run` to keep it. 19 test files use it. No row.
- **F5 — the sqlite trace callback reports the pin UPDATE twice.** One `execute`, one changed row; the statement is traced twice on a table with a `BEFORE UPDATE` trigger. Gate 3 counts changed rows instead. No row.
