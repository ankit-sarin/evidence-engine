### W1-F1-C1 — an exception after the paper's events are committed is recorded as that paper's extraction failure
- **File / function:** `engine/agents/extractor.py` :: `_extract_selected` (per-paper `try`)
- **Pattern:** iii (and ii)
- **Evidence level:** reproduced (the fault is injected; whether it occurs in the operator's run environment is not established — see "What goes wrong")
- **Evidence:** the `try` spans the extraction, whose events are committed inside it, and the bookkeeping after it:
  ```python
        try:
            result = extract_paper_with_completeness(...)      # write_extraction_events commits in here
            consecutive_failures = 0
            stats["extracted"] += 1
            stats["total_spans"] += len(result.fields)
            elapsed = time.time() - t_paper
            progress.report(pid, "EXTRACTED", elapsed)          # print(line, file=sys.stderr, flush=True)
            logger.info(...)
        except Exception as exc:
            ...
            stats["failed"] += 1
            ...
            progress.report(pid, "FAILED", elapsed)
            record_failure(pid, exc, "extract_pass2")
  ```
  `record_failure` → `outcome_for_exception` maps anything unlisted to `fail(PS.REASON_UNCLASSIFIED_ERROR)` → `write_extraction_events` writes an `extraction_failed` paper event. `plan_extraction_events` for a `PaperFailure` supersedes only claims whose reuse key differs (`_supersede_old_text_claims`), so the claims just written stay live.
  `repro/W1-F1/W1-F1_1_post_commit_exception.py` (one `BlockingIOError` raised from `ProgressReporter.report` on the success line; real `run_extraction`, real writer), `.out`:
  ```
  model calls made: 2
  stats: {'extracted': 1, 'failed': 1, 'total_spans': 20}
  extractor paper events, in order: [('extracted', 'extracted', None), ('extraction_failed', 'extraction_failed', 'unclassified_error')]
  live claims of the arm on the paper: 20
  effective_state: processing=extraction_failed reason=unclassified_error analysis_ready=False
  next run's selection: to_extract=[] skipped_asserted=[1]
  ```
- **What goes wrong:** a single failed write of the progress line (the only statement after the commit that can raise: `print(..., flush=True)` to stderr — `BlockingIOError` on a non-blocking stderr, `OSError` ENOSPC when stderr is a file) leaves a paper with 20 live claims and a last processing event `extraction_failed / unclassified_error`. It is not analysis-ready, and `select_for_extraction` skips it forever (`skipped_asserted`: the live claims carry the current reuse key), so no later run repairs it. It also counts +1 toward the 3-in-a-row abort, and the paper is counted in both `stats["extracted"]` and `stats["failed"]`. A persistently broken stderr does NOT produce this: the `FAILED` progress line in the handler raises again before `record_failure`, and the run stops loudly.
- **Refutation tried:** `record_call` (the other post-commit call, in `extract_paper_with_completeness`) cannot raise (its own `except Exception`); `check_completeness` and `logger.info` cannot raise (`logging` swallows handler errors); the elicited path returns straight after its write. So the trigger is the stderr print alone. No test pins the behaviour; no ruling on the `try`'s extent found (grep `progress.report`, `record_failure`, `_extract_selected` in the plan: D17 only, a different defect). 12f_C56-A handler #6 lists the faults that reach the handler from inside `extract_paper_with_completeness`; it does not consider an exception raised after the write.
- **Tests:** none covers it. `tests/test_extractor.py::test_input_fit_failure_fails_the_paper_and_the_run_continues` and `tests/test_cut_over.py`'s loop tests patch `extract_paper_with_completeness` and never fail a post-success statement.
- **Existing row:** extends C56 (handler #6: a new site — the handler also covers post-commit statements, so a non-run fault overwrites a stored paper's state; C56's ruled fix, a run-fault predicate re-raised ahead of the handler, would not narrow the `try`)
- **Proposed class / package:** 1 / P1 — a stored paper's state is made wrong and unrecoverable by selection; low likelihood, one-line narrowing of the `try`, same lines as C56's extract-path work.

### W1-F1-C2 — at budget exhaustion the stored outcome is the last attempt's alone
- **File / function:** `engine/agents/extractor.py` :: `extract_paper_with_completeness` (`last_error`), with `extract_paper`'s `exc.record = legacy_record(..., attempts=attempt or 1, ...)`
- **Pattern:** other (iv for the `attempts` figure)
- **Evidence level:** reproduced (with stubbed responses that differ between attempts; whether the model's replies differ between identical requests was not tested — no model call permitted)
- **Evidence:**
  ```python
        except RETRYABLE as exc:
            last_error = exc
            ...
            continue
    ...
    raise last_error
  ```
  Each refusal's record is built from that attempt only, stamped `attempts=attempt or 1`; `outcome_for_exception` returns `exc.record` for the one exception it is handed; a `ValidationError` carries no record.
  `repro/W1-F1/W1-F1_3_last_attempt_wins.py`, `.out`:
  ```
  --- case a: (attempt 1: A uncited; attempt 2: B uncited; attempt 3: C uncited)
  extractor paper events: [('extracted', 'extracted', None)]
    study_type: asserted value='attempt3' attempts=None violation_codes=None
    robot_platform: asserted value='attempt3' attempts=None violation_codes=None
    task_performed: contract_unmet value=None attempts=3 violation_codes=['VALUE_WITHOUT_CITATION']
  --- case b: (attempts 1 and 2: 19 cited fields each; attempt 3: unparseable JSON)
  extractor paper events: [('extraction_failed', 'extraction_failed', 'response_unparseable')]
    claim-bearing events stored: 0
  ```
- **What goes wrong:** (a) a field cited correctly on attempts 1 and 2 and uncited only on attempt 3 is stored `contract_unmet` with `attempts: 3` — the payload reads as "failed three times" when it is the paper's attempt number — and its two good values are gone; the paper is `extracted`, so selection never revisits it. (b) which attempt comes last decides between "19 fields stored" and "nothing stored, `response_unparseable`"; the reverse order (two unparseable, then a one-field response) stores the one field as `extracted`. The elicited path's inner loop states the opposite policy for the same situation ("attempt 2 replaces attempt 1 only if strictly fewer fields are unmet").
- **Refutation tried:** R139/R140 ("a paper stores what the arm produced"; "payload violation_codes and attempts") do not say which attempt; no ruling found for `last_error` (grep: no row or ruling names it). The request is re-issued identically at temperature 0 with no `seed` sent (R66), so identical replies are likely but not guaranteed (a proactive Ollama restart can fall between papers, not between attempts). If replies are always identical the candidate has no effect — which is A-11's "a deterministic collapse is likely to repeat three times".
- **Tests:** `tests/test_extraction_events.py::test_t4_a_duplicated_field_is_retried_then_contract_unmet` and `::test_t2_an_exhausted_uncited_value_is_contract_unmet_and_the_paper_stores` return the same spans on every attempt, so they cannot see it.
- **Existing row:** extends A-11 (same exhaustion path; new consequence: which attempt is stored, and what `attempts` means)
- **Proposed class / package:** 1 (weak) / P1 — a stored `contract_unmet` and its `attempts` can misstate what the arm produced; goes with A-11's R535 fix. A PI decision on the policy (last / best / first) is needed.
