## 5. Entry-point lock census

### 5.1 The lock implementation (READ, `engine/utils/ollama_lock.py`, whole file)

- **Path:** `~/.ollama_experiment.lock`, or `OLLAMA_EXPERIMENT_LOCK` (`:63-69`).
- **Acquire:** `hold_experiment_lock(blocking=True)` opens the file and calls `flock(LOCK_EX)`, blocking by default; `blocking=False` raises `BlockingIOError` (`:139-172`). Re-entrant inside one process through a depth counter (`:153-164`).
- **N22 holds:** the only log lines are after the acquire and after the release (`:177`, `:191`). Nothing is logged before a blocking wait.
- **Probe:** `check_experiment_lock()` takes and immediately releases a non-blocking lock on a second descriptor; an unopenable file reads as held (`:94-125`). `foreign_lock_held()` is "held, and not by this process" (`:128-135`).
- **Child refusal:** there is no child-specific code. A child of a holder that probes sees the parent's lock as foreign, so its restarts are refused. That is what A-1's "children of a holder are refused" describes (CODE ORDER).
- **INT-g12-7:** flock belongs to the open file description. A process started under an outer `flock` (or with an inherited fd 9) that then calls `hold_experiment_lock()` opens a second description and blocks on its own wrapper's lock, with no log line (CODE ORDER; measured at 12g, `12g_RA-A.md`).
- **Opt-out:** `EVIDENCE_ENGINE_NO_OLLAMA_RESTART` is read by `restart_disabled()` (READ, `engine/utils/ollama_client.py:38-43`). It is not a lock setting.

**How INT-g12-7 constrains each way the nightly could respect the lock.**

| Way | Constraint |
| --- | --- |
| Cron line or script wraps pytest in `flock <lockfile> …` | The lock's file description is inherited by pytest. Any test that calls `hold_experiment_lock()` on the same path then blocks on the wrapper's own lock. Tests do call it on the real path (F-1). **Deadlock; excluded** |
| Script takes `flock -n 9` and keeps fd 9 open (the health job's pattern) | Same inheritance unless the fd is closed for the child (`9>&-`). If closed for the child, the child's own acquire still blocks while the parent holds. **Excluded for the same reason** |
| Script probes and releases (`flock -n <lockfile> true`), then skips or runs | No deadlock. Leaves a window: a run can take the lock one second after the probe, mid-nightly. Harmless for the server only if the nightly no longer calls models |
| The suite checks in Python (a session-start hook calling `check_experiment_lock()`), exits with a "skipped" result | No deadlock, same window. Keeps the rule in the repository rather than in the crontab |
