R721(b) — U18's design is option (iv) of the read-out §6, built as two commits in this order, each
  with its own gate, the second not started before the first is ruled landed:
  Commit 1 (option (ii), "one host"): the engine resolves the Ollama host once, at import from
  OLLAMA_HOST with the library's default, into one function in ollama_client.py that every engine
  read uses — the chat client (H1), the digest read (H2/H3, through the engine's keep-alive client
  rather than a new httpx connection, finding 9), the preflight's ps (H8, through the engine client,
  not the library's module client), the restart poll (H10), and the local-service set (H4/H5, which
  becomes a predicate on the resolved host). No literal 11434 remains on the run path; the fence's
  loopback coverage (R626(c)) and the live-fence test are updated to name the resolved host and both
  loopback spellings, not to drop either. The manifest records the resolved Ollama host beside its
  `host` key where that key lives: if it is the manifest JSON (manifest_sha256 covers it), in this
  commit; if it is a run_manifests column, deferred to 023 (P6) and reported, with the JSON key
  still written. Tests: the host equality is proven by one test per read site that a rebound
  OLLAMA_HOST moves every site together; the live fence stays green.
  Commit 2 (option (iii), "the digest re-checked per call"): inside ollama_chat, under an active
  run, before the input-fit read and the send, the model's current digest (through the run's
  digest_fn, so the 26 injecting test modules keep working, and through the keep-alive client,
  ~2 ms) is compared with rm.stage_digest for the stage; a mismatch raises a RunRefused subclass
  named in the run-fault tuple (U02's predicate), so it propagates and the run closes
  ('aborted', a named reason) with no run_calls row for the refused call (C54's form). The
  n_ctx_train cache is keyed by the digest, not the host (finding 6), so a replaced tag cannot keep
  its old ceiling. Events need no change: a call that is sent carries the opening digest or the run
  has already refused (finding 7). Tests: a tag replaced between open and a call, and between two
  calls, each refuses with the named class and closes the run; the unchanged case sends the same
  request bytes; the check-to-send window is recorded as a limit in the read-out, not tested.
  Neither commit moves a request byte, the arm pin, or any prompt_hash (read-out §6, confirmed by
  the gates' pin and prompt-hash checks).
R721(c) — A non-loopback resolved host is refused at open_run with a named RunRefused subclass,
  before any read or write, in commit 1. The engine's product promise is that no paper text leaves
  the machine while cloud arms are empty; an OLLAMA_HOST that names another machine would send every
  prompt off-box through the local arm with nothing recorded. Declaring a remote Ollama host is a
  later capability (a Review Spec block, with the manifest recording the transfer as cloud arms do);
  it is not built here. The refusal is tested.

  host-equality refusal would need normalisation that commit 1 makes unnecessary.
