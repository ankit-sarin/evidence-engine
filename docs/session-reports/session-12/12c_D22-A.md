## Q1. How audit selects papers, and how a refusal can happen

**The predicate** (quoted in Q0):
- the paper is on the eligibility axis (`eligible_paper_ids`);
- AND it has live `asserted` claims for `arm` (`live_claim_events(conn, pid, arm, event_types=("asserted",))`);
- AND at least one of them has no `citation_located` event.

There is **no run filter**: any live asserted claim of the arm counts, from any run. The arm is
`spec.extraction_models.arm` (`_stage_audit`).

**What audit re-reads.** It calls `resolve_parsed_text(conn, pid)` and `read_parsed_text(ref)`.
`resolve_parsed_text` (`engine/core/parsed_text.py`):

```python
def resolve_parsed_text(conn: sqlite3.Connection, paper_id: int) -> ParsedTextRef:
    """The paper's current parsed text: its greatest recorded version."""
    row = conn.execute(
        "SELECT parsed_text_uid, paper_id, parsed_text_path, parsed_text_version, "
        "parsed_text_sha256 FROM parsed_text_refs WHERE paper_id = ? "
        "ORDER BY parsed_text_version DESC LIMIT 1", (paper_id,)).fetchone()
    if row is None:
        raise NoParsedText(paper_id)
```

and `read_parsed_bytes`, which raises `ParsedTextMissing` on `FileNotFoundError` and
`ParsedTextModified` when the file's sha256 differs from the recorded one.

**So audit does not re-read the sha that extraction used.** It reads the newest version, and verifies
the file against that version's own recorded hash. The claim's `parsed_text_sha256` (its payload and
`claim_inputs`) is never compared.

**The ways audit can be refused after extraction succeeded:**

| reason | possible? | why (quoted) |
|---|---|---|
| `parsed_text_missing` | **yes** | The newest version's file is deleted between the extraction run and the audit run, e.g. a Run 7 resume across days (R357), or an audit-only `--skip-to audit` run. `read_parsed_bytes` raises on `FileNotFoundError`. |
| `parsed_text_modified` | **yes** | That file is edited in place between the runs. `observed != ref.sha256` raises. R122: "The remedy for a modified text is a new version record (R95), never an in-place read." |
| `parsed_text_not_recorded` | **no** | Extraction needed a `parsed_text_refs` row (selection resolves one, D21), and the table is append-only on live: `parsed_text_refs_no_update` / `parsed_text_refs_no_delete` (`RAISE(ABORT, 'parsed_text_refs is append-only…')`). A row extraction used can never disappear. |

**F1 (adjacent, not a refusal): the text audit locates against can differ from the text the claim was
extracted from.** If the paper is re-parsed between extraction and audit, a new
`parsed_text_version` is appended. Audit then reads and locates against the new text, with no
refusal and no comparison to the claim's `parsed_text_sha256`. The `citation_located` payload records
the audit's own `parsed_text_sha256=ref.sha256`, and so does the `audited_ai` payload, so the
divergence is reconstructable after the fact but not checked. Live (`mode=ro`): **4 papers have more
than one parsed-text version.** This is outside D22's question and is recorded as a finding only.

**Is there a token that truthfully records "audit refused: parsed text <reason>"?** **No.**
- The reason codes exist (`parsed_text_missing`, `parsed_text_modified`), but only as reasons

- `extraction_failed` asserts that extraction failed, which is false for a paper with live asserted
  claims.
- The other failure tokens (`full_text_not_obtainable`, `parse_failed`, `input_exceeds_context`) name
