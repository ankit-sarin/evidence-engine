R685(b) — R624(b) is answered: no. The engine does not re-extract a paper the arm already holds
  on the ground that its recorded text file has changed or is missing. A held paper's claims are
  bound to the parsed_text_sha256 they were made from and stand; the engine's route to new
  claims is a re-parse to a new version, whose new bytes are a new reuse key and which D24
  already re-extracts (case (ii), paper 12). A file altered or removed under an existing
  reference is an integrity fault of the review's file store, which no engine path produces;
  today it is reported each run (claimed_text_unreadable, U11) and left, and its recorded form —
  a processing-axis token for a held paper whose text no longer verifies — is set by P6's Phase
  A with 023, D22's state and INT-s12-2's transition table. Candidates C (pin-affecting; cannot
  cover a missing file; resamples on an outside fault) and D (a one-paper fault is not a run
  fault) are rejected; B's principle is adopted and its build is 023's. test_text_refusal_at_
  selection.py gates 1–2 stand. INT-i12-69 gains a dated note carrying this and the reduction to
  cases (i) and (iii); its class and package are unchanged.
