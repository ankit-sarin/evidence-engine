## The question (R563, quoted)

> "No model call, no write, live mode=ro"

> "RD-4 (INT-g12-1): where units beyond the first are dropped on the way from the elicited output to the stored
> claim; whether the unit map keeps them; what the locator and auditor read."

> "North star unchanged: these reads inform engine decisions only."

## Answer

1. **Where they are dropped.** In `engine/elicitation/materialize.py`, `source_snippet`, which returns the
   first contiguous run only. `engine/elicitation/pipeline.py`, `extract_paper_elicited`, calls it when it builds
   each field's span. Everything downstream of that call sees one run.
2. **Whether the unit map keeps them.** The unit-map file keeps the text of every unit of the paper, so every
   dropped unit can be resolved (99 of 99 on `ra_12g`). It does **not** record which units a field cited. The
   citation set is kept in one place only: the telemetry sidecar `telemetry/extraction_calls.jsonl`, which is a
   gitignored file keyed by paper and attempt, not by claim. No field event carries it.
3. **What the locator and auditor read.** Both read the claim's stored `source_snippet`, that is, the first run.
   The locator checks that run against the parsed text. The auditor's semantic check runs only for a claim the
   locator did not find, and it is given the field, the value and that same snippet.

**Expectation check.** Two of the brief's three expectations held as written (the drop is where the elicited
output becomes the claim's snippet; the locator and auditor read only the stored snippet). The third — "the unit
map keeps every cited run" — held only in part: the unit text is kept, the citation set is not in the unit map.
This is a finding, recorded below; it does not change the read's question.

## Answer in the ruling's terms

- **Where dropped:** `materialize.source_snippet`, called from `extract_paper_elicited`; a deliberate choice,
  documented in the module, made when the store was `evidence_spans`.
- **Does the unit map keep them:** the unit text, yes; the citation set, no — that is in the telemetry sidecar
  only.
- **What the locator and auditor read:** the stored first run.

## PROPOSED class and package

**PROPOSED: Class 1 confirmed, package P1, storage-side.** CC proposes; the PI rules.

Reasoning, as CC's judgement. Each consequence is of the provenance kind Class 1 names:
- A claim's recorded evidence is narrower than the evidence the value was produced from. Pass 2 saw every cited
  unit; the claim shows one run. "Asserted with evidence" then means the first run was found, on half the claims.
- For an INFERABLE or JUDGMENT field the first run in index order is the earliest sentence in the paper, not
  necessarily the one that carries the value. A human auditor reading the claim reads that sentence.
- The only record of the full citation set is a file its own module calls disposable, outside the database, the
  fingerprint and the backup's notion of the review, and not keyed to the claim.

The docstring's reason ("`evidence_spans` has no column for a citation set") describes the legacy table. Claims
are now field events, whose `payload_json` already carries per-claim identity keys.

Options, with their relation to the pin (R539: what the elicited run sends):
- (a) **Record the citation set on the claim** — the sorted index list (or the runs) in the `asserted` event's
  payload. No migration, no change to any request, so **not pin-affecting**. Every claim then names all its
  evidence by unit index, resolvable against the unit map built from the parsed text the claim already names.
- (b) (a), plus **locate every run** at audit, one `citation_located` verdict per run or one event carrying a
  per-run list. Audit-side, outside the pin. It changes what "asserted with evidence" requires, so it needs a
  rule decision: all runs located, or any.
- (c) Leave as built and state the narrowing in the methods text. No code.

CC's PROPOSED choice: **(a) before the freeze, (b) decided with locator-2** (it is the same locator question as
RB-2's). (a) is small and it is the part that cannot be recovered after Run 7 except from a sidecar file.

One dependency, stated so it is not missed: (a) records indices, and an index means something only against the
unit map of that run. Row E-UNITMAP (Class 1, P1) is the open row on that link: the unit-map directory is keyed
by process time and "is linked to its run by nothing on disk" (its 12g note).
