## What changed

- **A unit is a `(start, end)` slice of the raw parsed text** (`engine/elicitation/units.py`, `UNITS_VERSION` `units-2`). `UnitMap` carries `spans` and `source_raw`; `units` holds the presented form. `source_stripped` and `strip_comments` are gone.
- **Comments are boundaries, not substitutions.** Units are built inside the stretches of text between comment spans. `COMMENT_RE` no longer lets a match contain a second opener, so an unterminated `<!--` before a later comment stays body text (Wave 1 row 7).
- **`sentence_spans`** is added to `analysis/provenance/segment.py`: the same segmentation as `sentences`, returning offsets, with the ellipsis kept on the sentence before it. `sentences` is unchanged for its other callers (`parse_quality.py`, `contracts.py`, `classifier.py`, `census.py`, `elicit01/units.py`, `parse01/sweep.py`).
- **`merge_short` joins spans**, start of the first to end of the last, within one comment-free stretch.
- **Presented and stored (D-a).** `presented()` collapses each whitespace run of the slice to one space; it is the only place the shown form is derived.
- **A run is one slice (R572)** and **the EXACT check (R534)**: `materialize.source_snippet` returns `source[start_first:end_last]` and raises `SnippetNotExact` unless that is the text at those offsets in the text it is checked against. The pipeline passes the parsed text the claim names.
- **D-b.** `SnippetNotExact` is added to `outcome_for_exception`'s re-raise tuple.
- The unit-map JSON records `spans`.
